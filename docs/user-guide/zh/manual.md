# Anti-Vocale 用户手册

Anti-Vocale 在您的 Android 设备上完全离线地转写语音消息。音频永远不会离开您的手机：转写在本地用开源 AI 模型完成，无需账号，没有云服务，也没有遥测。

本手册已更新至 1.15 版。

## 快速上手

1. 从您的应用商店（Google Play 或 F-Droid）安装 Anti-Vocale，或从 GitHub 上发布的 APK 安装。
2. 打开一次应用。在“模型”标签页您会看到可供下载的内置模型。
3. 下载一个模型。对大多数人来说，推荐的首选是 **Parakeet TDT（stock int8，640 MB）**：速度快、体积小，覆盖 25 种欧洲语言。
4. 要转写，从任意聊天应用（WhatsApp、Telegram、Signal 等）把语音消息分享给 Anti-Vocale。处理期间会出现一条通知，随后第二条通知带着文字。
5. 点按结果通知即可复制、分享文字，或把文字发回它来自的聊天。

其他配置一概不需要。下文的内容全部是可选项。

## 选择模型

各模型在体积、速度、语言覆盖和准确率上有所不同。“模型”标签页在下载前就会在每张卡片上列出关键信息。快速参考：

| 模型 | 体积 | 语言 | 说明 |
|---|---|---|---|
| Parakeet TDT stock int8 | 640 MB | 25 种欧洲语言 | 快速轻量；默认推荐 |
| Parakeet TDT SmoothQuant | 862 MB | 25 种欧洲语言 | 更准确也更重；需要更多内存 |
| Whisper Turbo | 988 MB | 101 种 | Whisper 家族中综合最均衡 |
| Whisper Medium | 903 MB | 101 种 | 比 Turbo 慢，对多数音频并没有更好 |
| Whisper Small | 358 MB | 101 种 | 最轻量的 Whisper；质量不错 |
| Whisper Distil Italian | 938 MB | 仅意大利语 | 内置模型中意大利语准确率最高 |
| Qwen3-ASR | 938 MB | 多语言 | 另一种架构 |
| Nemotron streaming | 640 MB | 多语言 | 边说边显示文字（流式）|
| GigaAM v3 | 326 MB | 俄语 | 俄语专精 |

经验法则：
- 如果您主要转写一种语言，同样体积下专用模型（Distil Italian、GigaAM）胜过通用模型。
- 如果手机内存为 4 GB 或更少，优先选择 500 MB 以下的模型。
- Gemma 模型（在“模型”标签页单独列出）是更大的语言模型，也能转写。它们适合试验，但比专用的 ASR 模型更重、更慢。

## 转写：日常流程

- 把语音消息分享给 Anti-Vocale。处理立即开始，即使屏幕已关闭。
- 结果通知提供：**复制**、**分享**，以及在来源应用受支持时的 **发送到 [App]**，后者把文字直接粘贴进语音消息所在的聊天。
- 开启自动复制（设置）后，通知到达时文字已经在剪贴板里；通知会说明这一点。
- 每条转写都保存在 **Logs**（历史）标签页中，附带所用模型、时长和处理时间。长按一条记录可重试、复制、删除，或通过邮件报告糟糕的结果；**重新转写**让您自选另一个模型重跑同一段音频。
- 使用 **Whisper 或 SenseVoice** 模型时，每条展开的转写都带一个语言标签：模型检测到的语言的旗帜，检测结果不对时点按即可查看或固定（小模型偶尔会猜错）。其他模型家族不报告检测到的语言，因此语言标签对它们保持关闭；设置里的开关会说明这一点并保持禁用。
- 自行检测语言的模型也可能判断失误。当一条转写的语言与手机系统语言明显不同时，文字下方的一行提示会指向语言设置，供支持该设置的模型使用。提示本身永远不会改变任何内容。
- 同一段音频分享两次，也不会不经询问就重复运行：如果该文件已用同一模型转写过，一个小对话框会提供打开现有结果或重新转写的选项。若有变化（换模型、上次运行失败），就直接重新转写。
- 开启自动保存到文件夹（设置）后，每条转写还会写成 .txt 文件，存入您选择的文件夹。

## WhatsApp 语音消息，自动转写

Anti-Vocale 可以在新 WhatsApp 语音消息到达的那一刻自动转写，完全无需点按。文字进入 Logs 标签页，并以结果通知出现；如果 Android 阻止后台启动（比如屏幕关闭时），一条一键通知会代为开始转写。

设置只要一分钟，在 **设置 > 语音消息** 中：

1. 打开 **语音消息转录**，并在 Android 询问时授予音频访问权限。如果您已经拒绝过两次，Android 不会再弹出对话框；此时出现的红色提示会打开系统页面，在那里仍可授予该权限。
2. 通过引导式选择器一次性选定 WhatsApp Voice Notes 文件夹。选错文件夹会被当场拒绝；您可以随时在同一张卡片上更改或移除它。
3. 可选：同时开启 **发送者识别**，并授予通知访问权限。此后 Logs 里的行会标出发送者名称。

有两条老实的规则约束这些标签。只有当语音消息自己的通知能确认名称时才显示名称，也就是说，通知在功能开启期间到达，并且它报告的时长与音频一致：名称从不靠猜。而您手动下载的语音消息（自动下载关闭时）保持无名，因为它们的通知太旧，不可信。近期通知的等待名单只保存在内存中，功能关闭即消失。

这里的隐私约定与其他地方完全一致：检测开启时，只读取 WhatsApp 语音消息文件夹的列表；某条语音的音频只在转写它时读取，且完全在本机进行；功能关闭时，什么都不读。

有一点要说清楚：在电池管理激进的手机上，系统挂起应用期间到达的语音消息可能被漏掉，直到应用醒来。如果您依赖自动模式，把 Anti-Vocale 从电池优化中排除可以让它变得可靠。目前仅支持 WhatsApp；Telegram 已在路线图上。

## 结果：标签、格式与悬浮窗

- **说话人标签**：在设置中开启后，对话转写会逐句标注说话人，在结果和所有导出中以 SPEAKER 轮次呈现。
- **播放**：原始音频可以直接从展开的行内播放。播放与暂停、可拖动的进度条、播放倍速，以及针对长停顿录音的跳过静音模式：直接跳过空白段，而不是把它们播放出来。
- **分享不止纯文本**：从结果行可以把转写分享为纯文本、带时间戳的文本、SRT 或 VTT。带时间戳的格式要求转写本身带有 cues。“Share as...”需在设置中主动开启。
- **画中画**：转写进行时，一个悬浮窗可以实时显示正在出现的文字，您可以继续使用其他应用。
- **重新转写**：直接在某一行上换一个模型重跑该条记录，然后对比。

## 长音频、队列与重试

- 任意长度的音频配任意模型都能用：较长的录音会被自动切分再拼接。（旧版本配合 Parakeet 有 6:40 的时长上限；现在没有了。）
- 连续分享多条消息：它们会排队。每条排队项都可以在它自己的通知上单独取消，同时另一条转写正在运行。
- 转写失败后，在 Logs 标签页一键即可重试。

## 社区模型与导入

内置目录并不覆盖所有语言。Anti-Vocale 自带一个社区模型目录，两次点按即可导入：模型标签页、高级、ONNX Sherpa、从目录导入、按您的语言筛选、点按模型、确认。目录在持续增长，目前收录 30 多个经过验证的条目：阿拉伯语（方言版，含完整版和轻量版）、德语（流式和一个 Whisper 微调）、西班牙语（流式和轻量版 Moonshine）、瑞士德语、希伯来语、波斯语、俄语、越南语、韩语、乌克兰语、六种印度语言（孟加拉语、古吉拉特语、印地语、马拉地语、泰米尔语、泰卢固语）、英语和法语的 Canary Flash、SenseVoice、Dolphin、Orukeet（一个覆盖 24 种语言、包括意大利语的 Parakeet 微调），以及一个低内存的多语言 Whisper Tiny。如果缺少您的语言，请开一个 issue：条目正是这样添加进来的。

高级用户还可以：
- 从 Hugging Face 仓库 URL 或目录条目链接导入模型（同一对话框中的高级分支）；
- 从手机上的某个文件夹导入一组模型文件；
- 把已下载的模型导出为 **离线包**，再到另一台设备上导入，这样下载过一次的模型无需重新下载即可迁移；
- 把应用指向由任何人维护的另一个目录索引（目录源旁边的“更改”操作），例如您的社区。

导入格式和文件要求见[外部模型](../../external-models.md)。

## Tasker 与自动化

Anti-Vocale 接受一个广播，Tasker（或任何自动化应用）都可以发送它来转写文件，无需触碰界面：

```
Action: com.antivocale.app.PROCESS_REQUEST
Extras: request_type=audio, file_path=/path/to/audio, task_id=your-id
Optional: backend_id=<model id> to pick the model for that request
```

结果通过一条回复广播返回。带示例的完整演示见 [Tasker 指南](../../TASKER_GUIDE.md)。

## 定时文件夹监视

Anti-Vocale 可以监视您选择的文件夹并自动转写新的音频文件：设置、定时文件夹监视、监视一个文件夹。扫描按系统允许的节奏进行；激进的省电模式可能拖延扫描，而手动的“立即扫描”永远有效。每个新的音频文件都用当前选中的模型转写，并像其他转写一样进入 Logs 标签页。在 Android 11 及以上版本中，文件夹选择器可以打开共享存储中的位置，比如某个聊天应用的媒体文件夹，这样无需逐条分享就能自动转写一个聊天的全部语音消息。

## 远程卸载（实验性）

如果您自己运行转写服务器，Anti-Vocale 可以把较长或较重的转写委托给它：设置、远程卸载（实验性）。任何使用 /v1/audio/transcriptions API 的 OpenAI 兼容服务器都可以（OmniVoice、whisper.cpp 服务器等）。应用内的说明写得很直白：该功能启用时，您所委托转写的音频只会发送到您输入的那个服务器地址，无论服务器在哪里（您的家庭网络或互联网上的任何地方）；其余一切都在设备上转写，而且该功能默认关闭。

## Open Transcribe（实验性）

支持开放 Open Transcribe 契约的应用，比如 Forkgram（一个 Telegram 客户端），可以把 Anti-Vocale 用作它们的原位语音消息转写器：开启 **设置 > 自动化 > Open Transcribe API**（默认关闭），然后在客户端的离线转写设置中选择 Anti-Vocale。语音消息用应用自己的模型转写，音频不会离开设备。关闭开关后，应用会重新从各客户端的选择器中消失。

## 按应用设置

对您分享来源的每个应用（WhatsApp、Telegram……）都可以单独配置：是否显示发回操作、是否自动复制，以及通知铃声。设置标签页，按应用设置。

## 备份与迁移

您的设置和全部转写历史可以搬到另一部手机。**设置 > 备份与迁移**会把一个 zip 压缩包导出到您选择的文件夹；在任何设备上导入都会把记录合并进本地历史，同一个压缩包导入两次也不会有任何变化。请像对待其中的数据一样对待压缩包文件：转写、发件人姓名和说话人标签都以明文存放在里面，拿到文件的人都能读取，导出操作在写入前也会明确说明这一点。

## 隐私

- 转写 100% 在设备上完成。任何音频、文字、元数据都不会离开您的手机。
- 应用没有用于转写的联网权限；只有您明确下载模型时才会使用网络。
- Logs 保存在您的设备上，属于您：随时可以在 Logs 标签页清空。
- 手动备份的压缩包（设置 > 备份与迁移）以明文存放转写、发件人姓名和说话人标签：拿到文件的人都可以读取。应用永远不会把压缩包发往任何地方；它只出现在您保存它的位置。
- Play 版包含 Crashlytics 崩溃报告（可在 Android 设置中查看并禁用）；F-Droid 版没有。

## 故障排查

**转写一直不结束，或通知消失了。**
一些手机厂商（vivo、OPPO、部分小米和三星）会激进地挂起后台应用。打开一次 Anti-Vocale，如果它提出，就授予电池豁免；或者在电池设置中找到该应用，将其设为“不受限制”。应用会检测到这种情况，并在发生时通过通知加以解释。

**“内存不足”，或使用大模型时崩溃。**
每个模型都在卡片上标明了体积。内存为 4 GB 或更少的手机请使用 500 MB 以下的模型。如果转写因内存不足而失败，请尝试更短的文件、更小的模型，或关闭其他应用。

**转写质量差。**
请尝试您的语言的专用模型（见上表）。在 Logs 中长按出问题的条目，用报告把详情发给我们（模型、时长、耗时；转写摘录仅在选择附上时才会包含）。

**开启 NNAPI 后崩溃。**
如果您在设置中启用了 NNAPI 提供方，随后应用崩溃，它会在下次启动时自动回退到 CPU。NNAPI 高度依赖手机的芯片组；如果反复崩溃，就继续用 CPU。

**自动语音消息不再到达。**
常见原因有两个。如果 WhatsApp 的文件夹被删除并重建过（重装、清理工具），已保存的文件夹权限可能失效：打开 设置 > 语音消息，在卡片上重新选择文件夹。如果您的手机激进地挂起后台应用，应用被挂起期间到达的语音消息会被漏掉，直到它醒来：前面提到的电池豁免就是解决办法，而且它对这个功能比对手动分享更重要。

## 常见问题

**没有网络也能用吗？**
能。下载一个模型后，转写完全离线可用。

**支持哪些聊天应用？**
任何能分享音频文件的应用。发回操作目前面向一部分应用（WhatsApp、Telegram 以及其他自动检测到的应用）。

**我的转写在哪里？**
在 Logs 标签页，以及可选地保存为您所选文件夹中的 .txt 文件。其他任何地方都不存储。

**语音消息到达时能自动转写吗？**
能，针对 WhatsApp：开启 设置 > 语音消息，授予音频访问权限，并一次性选定 WhatsApp Voice Notes 文件夹。新消息一到达就被转写，行上还能带发送者名称。定时文件夹监视仍然是任何应用媒体文件夹的通用途径（Android 11+），Telegram 已在路线图上。在电池管理激进的手机上，应用被挂起期间到达的消息可能被漏掉：电池豁免能让自动模式变得可靠。

**为什么某条语音消息没有发送者名称？**
只有当该消息的通知在发送者识别开启期间到达，且通知报告的时长与音频一致时，才显示名称。手动下载的消息（自动下载关闭）和通知从未到达的消息有意不显示名称：错误的名称比没有名称更糟。

**为什么有两个商店（Play 和 F-Droid）？**
同一个应用，同样的功能。F-Droid 从源码构建，不含任何专有组件；Play 版增加自动崩溃报告。

**它真的私密吗？**
真的。源代码是开放的；您可以核实没有任何数据离开设备。参见代码仓库中的隐私政策。
