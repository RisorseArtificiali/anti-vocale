# TASK-956 German lane: bench + convert (primeline/whisper-large-v3-german, GH #183)

**Date:** 2026-11-03 · **Scope:** the German community-catalog lane: bench the incumbents on FLEURS de_de, convert `primeline/whisper-large-v3-german` to sherpa int8 through the proven fi pipeline (TASK-769), measure it on the same 40-clip protocol, and give a GO/NO-GO against Whisper Turbo. This report is a new file; nothing was committed, pushed, published, or cataloged (STOP point per the lane plan: before HF upload, catalog entry, and device pass).

## TL;DR

The conversion lane worked end to end (every validation gate passed, first try, with the fi pipeline applying UNCHANGED once the tokenizer was verified), but the candidate LOSES the bench: **7.48 WER vs Turbo's 6.01** on the same 40-clip de_de protocol (24% relative WORSE), at 1.72x Turbo's download size and ~3.3x its decode time on this harness. Recommendation: **NO-GO** for the catalog entry. Turbo (built-in) stays the German pick. The error profile shows no pathology (fluent, correct German; the counted misses are orthography variants like grosser vs großer, and numeral spell-outs such as siebzig vs 70, the same class every model eats on jiwer-normalized FLEURS), so this is a genuine model-vs-domain result, not a conversion artifact.

## Conversion record

**Toolchain (era-matched, identical to the fi lane):** torch 2.3.1, onnx 1.16.2, onnxruntime 1.18.1, numpy 1.26.4, transformers 4.44.2, openai-whisper 20250625 (its `disable_sdpa`); the export scripts copied from the fi sherpa worktree (sherpa-onnx sources at the pinned srclib commit af2d8d81, v2.0.1, plus the fi patches) into `/var/tmp/de-lane/scripts/`, with `large-de` added to `load_model` (loads `./large-de.pt`), `ALIGNMENT_HEADS` (USE_MODEL_METADATA), and the 128-mel branch; `per_channel=True` kept on the decoder quantize (GOTCHA 2a; the skill notes this exact model survived per-tensor in an August probe, but the pipeline standard is per-channel and the tiled test below is the gate). Export via `export-onnx-with-attention.py` (4-output decoder plus `n_alignment_heads` metadata); torch 2.3.1 predates the dynamo-exporter landmine (GOTCHA 2b, fi-verified).

**Deviations from the fi conversion (both verified before writing, both benign):**
1. `proj_out.weight` is ABSENT from the safetensors: the projection is structurally tied (transformers `tie_word_embeddings` default). The fi checkpoint stored both copies and they were verified equal; here there is nothing to check, and the embed permutation covers the output head by construction.
2. The checkpoint is bfloat16 (fi was fp16). bf16 to fp16 is exact for in-range values (7 to 10 mantissa bits); a magnitude guard found max |value| 5.34 across all 1259 tensors, so the fp16 .pt cast (the openai convention) is lossless here.

**Validation (all run and read this session):**
- .pt vs HF pipeline agree-check (greedy): probe0 transcripts identical; probe3 identical in all 31 words with one comma differing (a numeric tiebreak between the two implementations, not a mapping error; a wrong permutation produces garbage, not a comma).
- sherpa int8 decodes both probes verbatim to the HF ground truth.
- Tiled 62s probe (5 clips concatenated): the 30s window decodes 38 words across 3 sentences; no premature EOT (the per-tensor-int8 failure mode).
- fp32 vs int8 word agreement: 18/18 (100%) on probe0; 37/38 (97.4%) on the tiled window, one casing wobble (Sie vs sie), no truncation or collapse.
- Timestamps (the -attn contract): `enable_token_timestamps=True` (a constructor kwarg in sherpa 2.0.1; the fi archive script's method-call form raises AttributeError here) returns real DTW timestamps on 32/32 tokens, monotonically non-decreasing; decoder carries the 4 outputs including `cross_attention_weights`; encoder metadata `version 2`, `n_mels 128`, `model_type whisper-large-de`.
- Known deviation, same as fi: `n_alignment_heads` is 320 (openai-whisper's default last-half-of-layers set, layers 16-31 x 20 heads) instead of a curated head list, because the hand-built .pt cannot carry the official checkpoint's alignment dump; affects timestamp head count only, not WER.

## GO/NO-GO

**NO-GO** for the catalog entry. The bar was "clearly beat Turbo de WER" (fi precedent ~20% relative, i.e. <= ~4.8); the candidate measured 7.48 against Turbo's 6.01, on the standard protocol, with both incumbent WERs reproducing the matrix exactly the same day and the conversion validated at every level. A 1.78GB, RTF-1.5x model that does not win on quality has no case for the catalog; Turbo (built-in) remains the German recommendation, and #183 gets the honest negative with this evidence. What the lane DID produce: the conversion pipeline is now two-for-two on HF-layout whisper fine-tunes with zero adaptations beyond the tokenizer check the skill already mandates, and the tokenizer check itself was a no-op diff this time (both files byte-identical to stock, permutation unchanged).

Possible follow-up for a German-specific quality option (NOT benched this session, out of scope): the card itself points at `primeline/whisper-large-v3-turbo-german` (809M, turbo-class, marked `new_version`), which would trade at Turbo's own size and speed class rather than 1.78GB; that would need its own lane before any claim.
