# Model Scout Report — 2026-05-13

## Executive Summary

Four days since last report. **Two significant new model families appeared**: IBM Granite Speech 4.1 2B (Apache 2.0, 6 languages but no Italian ASR) and csukuangfj2 streaming Parakeet English models (6 variants with 240/560/1120ms chunk sizes). **Cohere Transcribe now has a third-party ONNX conversion** with Italian support and KV-cache decoder split — the most actionable finding, though not in sherpa-onnx format. **No new framework releases** since sherpa-onnx v1.13.1 (2026-05-08). No progress on any tracked blocked items (VibeVoice, llama-bro, Gemma 4 GGUF).

## ASR Model Findings

### IBM Granite Speech 4.1 2B
- **Source:** https://huggingface.co/ibm-granite/granite-speech-4.1-2b
- **Size:** 2B params (safetensors)
- **Languages:** EN, FR, DE, ES, PT, JA (6 languages). Italian ONLY for English-to-Italian speech translation, NOT Italian ASR.
- **Last updated:** 2026-04-29
- **Format:** safetensors (PyTorch). Multiple ONNX conversions available: `onnx-community/granite-speech-4.1-2b-ONNX` (2026-05-13, 40 files with fp32/fp16/q4/q4f16/quantized variants), `christopherthompson81/granite-speech-4-1-2b-onnx` (2026-05-09), `valoomba/granite-speech-4.1-2b-plus-ONNX` (2026-05-07). GGUF: `ibm-granite/granite-speech-4.1-2b-GGUF` (2026-05-11), `staghado/granite-speech-4.0-1b-GGUF` (2026-05-11). Non-autoregressive variant: `ibm-granite/granite-speech-4.1-2b-nar`.
- **sherpa-onnx compatible:** No — no csukuangfj conversion exists
- **Italian quality assessment:** N/A — no Italian ASR capability
- **Score:** 2.0/10 (no Italian ASR 1/5, 2B params 3/5, no sherpa-onnx 2/5, only 6 langs 2/5, Apache 2.0 IBM-backed 5/5)
- **Recommendation:** **watch** — If IBM adds Italian ASR in a future version, this becomes highly relevant. The dual-head CTC encoder architecture and non-autoregressive variant are interesting. The 1B GGUF variant at `ibm-granite/granite-4.0-1b-speech-GGUF` is in our size range but same language limitation.
- **Effort to integrate:** High — would need custom ONNX Runtime integration or wait for sherpa-onnx support
- **Notes:** 173K downloads. Licensed Apache 2.0. The onnx-community conversion has encoder + decoder_model_merged with multiple quantization options. Also has a `plus` variant with speaker diarization and word timestamps, and an `nar` (non-autoregressive) variant for higher throughput.

### csukuangfj2/sherpa-onnx-nemo-parakeet-unified-en-0.6b-streaming-* (6 variants)
- **Source:** https://huggingface.co/csukuangfj2/sherpa-onnx-nemo-parakeet-unified-en-0.6b-int8-streaming-560ms (and 5 others)
- **Size:** Unknown (files uploaded 2026-05-12, sizes not yet available via API — likely similar to non-streaming Parakeet ~200-300MB int8)
- **Languages:** English only
- **Last updated:** 2026-05-12
- **Format:** ONNX (encoder + decoder + joiner + tokens.txt), both fp32 and int8 variants
- **sherpa-onnx compatible:** Yes — produced by csukuangfj, in standard sherpa-onnx format
- **Italian quality assessment:** N/A — English only
- **Score:** 2.5/10 (no Italian 1/5, small model 4/5, sherpa-onnx native 5/5, English only 1/5, active maintainer 5/5)
- **Recommendation:** **watch** — English only, so not directly usable. But the streaming architecture (chunked encoder with 240ms/560ms/1120ms chunk sizes) demonstrates sherpa-onnx's streaming transducer capability. If csukuangfj produces a multilingual streaming variant of Parakeet TDT 0.6b v3, it would be directly applicable for our VAD+segmentation work.
- **Effort to integrate:** Low (if multilingual variant appears) — same sherpa-onnx API, just needs streaming config
- **Notes:** 6 variants total: streaming-{240ms,560ms,1120ms} × {fp32,int8}. Also a non-streaming variant at `csukuangfj2/sherpa-onnx-nemo-parakeet-unified-en-0.6b-int8-non-streaming`. This is the first time csukuangfj has published streaming Parakeet transducer models with explicit chunk sizes. The chunk sizes correspond to encoder subsampling rates — likely relevant for real-time/online ASR.

### christopherthompson81/cohere-transcribe-03-2026-onnx
- **Source:** https://huggingface.co/christopherthompson81/cohere-transcribe-03-2026-onnx
- **Size:** Unknown (LFS, sizes not available via API). Base model is 2B params. README mentions "7 GB → 120 MB" optimization via positional embedding deduplication, but this refers to encoder only. Full model likely 1-2GB.
- **Languages:** 14 languages including **Italian** (AR, DE, EL, EN, ES, FR, IT, JA, KO, NL, PL, PT, VI, ZH)
- **Last updated:** 2026-05-06
- **Format:** ONNX with KV-cache decoder split (encoder.onnx + encoder.onnx.data, decoder_init.onnx, decoder_step.onnx, mel.onnx, vocab.json)
- **sherpa-onnx compatible:** No — custom ONNX Runtime format, not sherpa-onnx's expected layout. Designed for [Vernacula](https://github.com/christopherthompson81/vernacula).
- **Italian quality assessment:** Unknown for Italian specifically. Base Cohere model is competitive but no Italian WER benchmarks found.
- **Score:** 5.0/10 (has Italian 4/5, unknown size 3/5, not sherpa-onnx 1/5, 14 langs 4/5, community conversion 3/5)
- **Recommendation:** **evaluate** — The most actionable new finding. This is a third-party ONNX conversion of the Cohere Transcribe model with Italian support. Has proper mel spectrogram frontend + encoder + KV-cache decoder (init/step split). However, requires custom ONNX Runtime integration since it's not in sherpa-onnx format. Worth evaluating Italian quality before investing in integration.
- **Effort to integrate:** High — would need a new `CohereTranscriptionBackend` with custom ONNX Runtime inference pipeline. The mel → encoder → decoder_init → decoder_step loop with KV cache is well-documented in the README. Apache 2.0 license.
- **Notes:** 40 downloads. README reports 38× realtime on RTX 3090. Interesting technical details: fp32 encoder + fp16 KV-cache hybrid (fp16 encoder caused hallucinations), `input_lengths` masking fix for batch padding contamination, IOBinding output ordering matters for decoder. The `torch.export` dynamo path was used with KV-cache split as default. This is the second tracked Cohere conversion (first was `AEmotionStudio/cohere-transcribe-03-2026-models` in safetensors).

## Landscape Developments

**IBM Granite Speech 4.1** represents a new entrant in the compact ASR space (2B params, Apache 2.0). Its dual-head CTC encoder with both graphemic and BPE outputs is architecturally interesting. The non-autoregressive (NAR) variant could offer throughput advantages for real-time use cases. However, the 6-language limitation (EN/FR/DE/ES/PT/JA) leaves Italian users underserved. The rapid appearance of multiple ONNX conversions (onnx-community, christopherthompson81, valoomba, smcleod) within days of release shows strong community interest.

**Sherpa-onnx streaming transducers**: csukuangfj published the first streaming Parakeet transducer models with explicit chunk sizes (240ms, 560ms, 1120ms). This demonstrates that sherpa-onnx's streaming infrastructure for NeMo transducers is maturing. Currently English-only, but the pattern could extend to the multilingual Parakeet TDT 0.6b v3.

**Cohere Transcribe ONNX ecosystem**: Three independent ONNX conversions of Cohere Transcribe now exist (christopherthompson81, AEmotionStudio, aoiandroid/CoreML). The christopherthompson81 version is the most technically sophisticated, with KV-cache decoder splitting and detailed documentation of export optimizations.
