# Model Scout 2026-11-11

**Scope:** full. **Baseline:** sherpa-onnx v2.0.1 (our pin, still latest), LiteRT-LM 0.17.1 ours / 0.19.1 latest, community catalog as shipped in v1.16.0 (39 entries). Previous report: 2026-11-08 (its headline, Parakeet Ultra, shipped in v1.16.0 with our own FLEURS bench as the gate).

## Executive Summary

Six findings since Nov 8. The headline is a Finnish gap-filler: RASMUS Finnish-ASR-Canary-v2 reports 7.75 WER on FLEURS-fi, against our own measured 14.48 for the just-shipped Parakeet Ultra and 20.66 for the v3 default; that is half the error of our best Finnish, in the Canary import family we already catalog. Second tier: Parakeet Redux int8 (a 327MB-download 25-language variant, at a measured quality cost), a near-lossless int4 Qwen3-ASR export that would cut our heaviest built-in from 937MB to 602MB, and the Nemotron-unified 0.6B conversion to watch. Frameworks: no releases since the last scout.

## ASR Model Findings

### RASMUS Finnish-ASR-Canary-v2 (HEADLINE: the Finnish gap)

- **Source:** https://huggingface.co/RASMUS/Finnish-ASR-Canary-v2 (NeMo format; base nvidia/canary-1b-v2)
- **Size:** est ~1.1GB int8 after conversion (1B params; unconverted today)
- **Languages:** fi only. Finnish is a requested tradition language (2026-10-06) with NO dedicated model today (covered only inside the Parakeet/Whisper multilingual sets)
- **Last updated:** 2026-03-02 (stable; 1,076 downloads)
- **Format:** NeMo Canary (needs our conversion pipeline; Canary is import family #5)
- **sherpa-onnx compatible:** after conversion (the Canary 180M Flash precedent, catalog entry from issue #71)
- **Import path:** community catalog (Canary family) via community-model-conversion
- **Quality assessment:** card-published WER 4.58 (Common Voice fi test) and 7.75 (FLEURS fi test). Cross-source caveat: those are the author's numbers with a `kenlm` tag on the card (shallow-fusion decoding may be included; our harness decodes pure). Against OUR OWN FLEURS-fi numbers: v3 stock int8 20.66, Ultra int8 14.48 (both measured 2026-11-08, eval/fleurs40_*_fi_fi). Even with fusion discount, the margin is large. Confidence: medium (author numbers, same test set family as our harness).
- **Score:** 3.9/10 (quality 5 for fi specifically, size 3, on-device 3, coverage 5, catalog 4, maintenance 3; weighted 3/2/2/1/1/1)
- **Recommendation:** evaluate. Run the conversion pipeline's Canary path on it, then our FLEURS-fi harness leg (the number to beat is Ultra's 14.48) and a real-voice-note Finnish clip set before any catalog entry
- **Effort:** medium (Canary conversion proven at 180M; 1B is the same export path, device-validation pass mandatory; memory needs a phone leg: Canary 1B int8 may exceed the RMX3853 comfort at ~1.2GB RSS)
- **Notes:** feature_dim 128 (Canary family standard, our chunk-cap machinery applies); check whether the card's kenlm fusion is load-bearing before promising the 7.75

### Parakeet TDT 0.6B Redux int8 (the budget 25-language variant)

- **Source:** https://huggingface.co/csukuangfj/sherpa-onnx-nemo-parakeet-tdt-0.6b-redux-int8 (fp32 twin alongside; base moondream/parakeet-redux = a 1.58-bit ternary re-train of v3, decoded to dense for ONNX)
- **Size:** 327,736,417 bytes int8 tarball (vs 487MB Ultra int8, ~640MB v3 stock); unpacked ~670MB; the saving is the DOWNLOAD, not disk
- **Languages:** same 25 EU set as v3/Ultra (no new coverage)
- **Last updated:** 2026-11-07 (export request k2-fsa/sherpa-onnx#4161)
- **Format:** sherpa-onnx int8 transducer, drop-in
- **sherpa-onnx compatible:** yes, pre-converted
- **Import path:** community catalog (Transducer family), direct entry, no conversion
- **Quality assessment:** the exporter's own FLEURS table (300 clips/lang, one harness): Redux int8 vs v3 int8: WER worse on en (13.86 vs 11.16), de (11.00 vs 6.84), fr (10.97 vs 8.69), el (49.46 vs 46.64); BETTER on mt (39.74 vs 56.41); six-language average 21.68 vs 22.38 (and Ultra 19.16). The card is explicit: int8 quantization hurts Redux far more than v3/Ultra (en fp32 7.62 -> int8 13.86) because the ternary scales resist per-channel quantization; "pick it when the smaller download matters... not as a general replacement for Ultra." Confidence: high (own-harness table on the card).
- **Score:** 4.0/10 (quality 3, size 5, on-device 5, coverage 2, catalog 5, maintenance 4)
- **Recommendation:** evaluate-then-catalog as the BUDGET variant ("Parakeet TDT 0.6B Redux (compact download)"), only if a 2-3 language spot-check on our harness reproduces the card's ordering; it is strictly a download-size play for metered-data users, never a quality play
- **Effort:** low (direct entry; device-validation pass; the long-audio/silence-split caveat is the same as v3/Ultra)
- **Notes:** frontend quiet-input issue shared with the family (k2-fsa#4024); the fp32 twin is NOT catalog material at ~1.9GB

### Qwen3-ASR 0.6B int4 (the memory cut for our heaviest built-in)

- **Source:** https://huggingface.co/goodpixelltd/qwen3-asr-0.6b-int4-sherpa-onnx
- **Size:** 602MB on disk vs 937MB for the int8 files we ship; loaded memory 0.77 -> 0.54GB, peak on 60s audio 2.3-2.6 -> 1.6-1.7GB (iPhone 14 Pro measurements)
- **Languages:** card evaluates zh/yue/en (base model's 59 presumed retained; our coverage unchanged)
- **Last updated:** 2026-11-09
- **Format:** sherpa-onnx with MatMulNBits 4-bit weights + external .weights data (needs onnxruntime >= 1.20; sherpa 2.0.1 ships 1.28.2)
- **sherpa-onnx compatible:** claimed; UNPROVEN in our build (the loader must accept the int4 ops and external-data mapping; this is the probe gate)
- **Import path:** built-in file-set swap (Qwen3 is not one of the seven import families)
- **Quality assessment:** CER on 500 YouTube clips (HK/TW/Mainland): 23.1/9.0/4.5 vs int8's 22.9/8.9/4.4, effectively lossless. Confidence: medium-high (single source, clean methodology on the card).
- **Score:** 3.7/10 (quality 4, size 5, on-device 4, coverage 3, catalog 1 (built-in only), maintenance 3)
- **Recommendation:** probe on device first (does sherpa-onnx 2.0.1's Qwen3 path load the int4 files at all?), then a FLEURS 2-language spot-check vs our int8; if both pass, swap the built-in file set in the next release (a ~35% download cut and a large RAM cut on the model our users most often OOM on)
- **Effort:** low-medium (no code change if the loader accepts it; catalog pin rehash + release)
- **Notes:** audio >35s needs max_total_len raised or silence-split (we already split); the memory numbers alone justify the probe

- **Import path:** unclear until the base card names languages; potentially built-in streaming replacement or catalog entry

- **Score:** 3.0/10 (all provisional)
- **Recommendation:** watch. Scrape the NVIDIA base card next run (sparse today); if it covers the 45-language streaming set at 0.6B it becomes a first-tier candidate

## Landscape Developments

- **Google AI Edge Gallery added on-device ASR/TTS (Nov 10, developers.googleblog.com):** Google ships compact multilingual ASR in the Gallery app via the MediaPipe AudioTranscriber path, the same rail as the litert-community parakeet above. Signals Google pushing the .litertlm ASR format; relevant only if we add that runtime.
- **Interspeech 2026 "efficient audio at the edge" (ADI recap):** Samsone audio-language models (Whisper-Tiny encoder + SmolLM2 decoder, 99M/134M/356M) for on-device listen-and-respond; KiloVAD, a 2,100-parameter convolutional VAD with 200ms context. KiloVAD is the interesting one for us long-term (our VAD is silero-class; a 2K-param VAD would cut preprocessing cost), but our current VAD works and swapping it is a research task, not a scout action.
- **Meta Omnilingual ASR won a TIME Best Inventions slot:** context only; the 300M CTC sherpa conversions of it remain the practical artifact (already in our catalog pipeline discussions, issue #69's Omnilingual ask).
