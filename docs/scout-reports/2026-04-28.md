## ASR Model Findings

- **Source:** https://huggingface.co/pszemraj/parakeet-tdt-0.6b-v3-gguf
- **Size:** F16 (~1.1GB), Q8_0 (~600MB estimated)

- **sherpa-onnx compatible:** No — GGUF format, would need llama.cpp/llama-bro runtime
- **Italian quality assessment:** Unverified — transducer architecture through GGUF inference is untested
- **Score:** 4.2/10 (Italian quality unverified 3/5, size OK 3/5, not sherpa-onnx 1/5, multilingual 4/5, community 2/5)

- **Effort to integrate:** High — would need custom GGUF transducer support in llama-bro
- **Notes:** 0 downloads. Proof-of-concept showing Parakeet can run through GGUF, but no quality validation. The CrispASR project is worth monitoring for GGUF-based ASR tooling.

- **Source:** https://huggingface.co/nzyaltair/Qwen3-ASR-0.6B-gguf
- **Size:** int4 ONNX encoders + Q4_K GGUF decoder (~400MB estimated total)
- **Languages:** 52 languages including Italian
- **Last updated:** 2026-04-25
- **Format:** Hybrid — ONNX int4 encoders + GGUF decoder
- **sherpa-onnx compatible:** Partially — encoders are ONNX but decoder requires GGUF runtime
- **Italian quality assessment:** Unknown — same base model as existing 0.6B variant but through a different decoder runtime
- **Score:** 5.0/10 (Italian quality same base 3/5, size good 4/5, hybrid complexity 2/5, multilingual 5/5, community 3/5)
- **Recommendation:** **watch** — the hybrid ONNX+GGUF approach is novel; if quality is proven, it could reduce decoder memory usage
- **Effort to integrate:** High — requires coordinating two inference runtimes (sherpa-onnx for encoders, llama-bro for decoder)
- **Notes:** 176 downloads. Files: `qwen3_asr_encoder_backend.int4.onnx`, `qwen3_asr_encoder_frontend.int4.onnx`, `qwen3_asr_llm.q4_k.gguf`. The int4 encoders are interesting for size reduction independently.

## Landscape Developments

### Parakeet ecosystem diversifying rapidly
The Parakeet model family is seeing community ports to every major runtime: GGUF (CrispASR), CoreML (485K downloads on `FluidInference/parakeet-tdt-0.6b-v3-coreml`), LiteRT/TFLite (with Qualcomm device-specific builds), and browser ONNX. This shows strong adoption but no new NVIDIA architecture (v4) is announced.

### Qwen3-ASR community fine-tuning explosion
In the 2 days since the last scout, multiple language-specific Qwen3-ASR fine-tunes appeared: Dutch, Japanese, Portuguese, Hungarian, Latin Spanish, and Ugandan. A diarization variant is in development by mrfakename. The ecosystem is very active, but no Italian-specific fine-tune exists yet.

### Qualcomm NPU benchmarks set expectations
Qualcomm's Distil-Whisper publication shows Whisper decoder at 5-12ms on Snapdragon NPU. For comparison, Anti-Vocale's CPU decoder takes ~1-2 seconds for the same work. This highlights the potential performance gain from NNAPI/NPU offload (relevant to TASK-95).

### Moonshine: still no Italian
Moonshine language variants now include Chinese, Vietnamese, Ukrainian, Korean, Japanese, and Arabic. Italian remains absent. The streaming GGUF variants are seeing active development.
