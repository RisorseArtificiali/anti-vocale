  - **Security fixes**: Path traversal validation, input validation across operators

## Addendum (main-session verification + Granite deep-dive)

### Corrections after verification

- **slyusarev/parakeet-tdt-0.6b-v3**: DOWNGRADED from high priority to noise. Verified from the repo README: it is a *byte-identical mirror* of istupakov/parakeet-tdt-0.6b-v3-onnx (same SHA-256), which is what our bundled catalog already ships. A mirror existing for another app (Textolit) is not a finding for us.
- **rhasspy/qwen3-asr-0.6b-onnx-int4-merged**: real but for a DIFFERENT runtime (onnx-asr/transformers.js style with external .data files + embed_tokens.bin). Our Qwen3-ASR path uses sherpa-converted exports; adopting this would mean a new file layout, not a quality change. Watch, not act.

### Granite Speech 5.0 Turbo CTC (the trigger for this scout)

Source: IBM Research blog 2026-08-25 + HF model card + WebGPU demo space, all verified.

| Field | Value |
|---|---|
| Model | ibm-granite/granite-speech-5.0-470m-turboctc (+ -nc variant) |
| Params | 470M (BF16, ~946 MB fp32) |
| Languages | **English only** (HF tags: language=en) |
| License | Apache 2.0 (base) / CC-BY-NC-SA-4.0 (nc) |
| Architecture | CTC conformer, 16 blocks, block-attention (ctx 128), 80 logmel + deltas, 8x subsampling, BPE vocab 16,384 |
| WER (public OpenASR, en short-form) | 5.00% aggregate Apache variant / 4.85% nc |
| Speed | 12,600 RTFx on H200 (GPU-only claim; no CPU/edge numbers exist; WebGPU demo ~300ms/10.24s window on M1 Max) |
| ONNX | none in the official repo; the IBM WebGPU demo ships a q4f16 ONNX (312 MB) via transformers.js |

**Verdict: NOT relevant for Anti-Vocale today.** English-only kills the primary criterion (Italian, weight 3x). The Granite 4.2 *language* models list Italian among 12 supported languages, but those are 3B-30B text LLMs, not ASR, and far outside our on-device envelope.

**Why it still matters (watch list):**
1. The size/speed point (470M CTC, no LLM backbone, streaming) is exactly our size class. If IBM ships a multilingual 5.x CTC with Italian, it lands directly against Parakeet/Distil-IT with a fraction of the size.
2. The architecture is CTC-conformer like our GigaAM path, but with custom IBM modeling code (block attention, self-conditioning): sherpa-onnx conversion is medium-high effort and would need a new config type. Precedent: our TASK-397 pipeline (HF-to-sherpa conversion) applies if it ever gains languages.
3. The nc variant's CC-BY-NC-SA license is a non-starter for our distribution (F-Droid + Play); only the Apache base would be eligible.

Score (composite per skill rubric): Italian impact 1, size efficiency 5, on-device feasibility 2 (no onnx export for sherpa), multilingual breadth 1, maintenance 4 => composite (1*3+5*2+2*2+1*1+4*1)/9 = 2.4/5. Watch, not pursue.
