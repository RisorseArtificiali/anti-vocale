## Landscape Developments

### LiteRT/TFLite emerges as alternative ONNX runtime for mobile ASR
Google's LiteRT ecosystem (evolved from TensorFlow Lite) is gaining traction for on-device ASR. Both Qwen3-ASR 0.6B and Parakeet CTC 0.6b now have official TFLite conversions with Qualcomm Hexagon DSP-specific builds. Argmax's commercial ParakeetKit Pro validates Parakeet on Android via LiteRT with reportedly industry-leading latency. This creates a potential future path: sherpa-onnx for ONNX Runtime inference (our current approach) vs. LiteRT for NPU-accelerated inference on Qualcomm chips. The LiteRT models are device-architecture-specific (SM8450 through SM8850), which complicates distribution but enables hardware optimization. Not actionable today but worth monitoring.

### Cohere enters open-source ASR with Transcribe
Cohere's Transcribe model (2B params, 14 languages, Apache 2.0) is the first major non-Whisper, non-Parakeet ASR model with Italian support in the sherpa-onnx ecosystem. At 1.6GB int8 it's too large for our mobile constraints, but its existence is significant: it validates the conformer encoder-decoder architecture (different from both Whisper's encoder-decoder and Parakeet's transducer) as a viable ASR approach. If Cohere or the community produces a distilled sub-1B variant, it could become a competitive option.

### Gemma 4 GGUF path is doubly blocked: architecture AND text-only
The GGUF path for Gemma 4 has two independent blockers:
1. **SDK profile issue:** llama-bro fork (`v1.3.0-gemma4`) adds native `LLM_ARCH_GEMMA4` support, but the Kotlin SDK's `ModelProfiles.GEMMA` doesn't configure Gemma 4 hyperparameters correctly. The GGUF download UI section in `ModelTab.kt:500-502` remains commented out.
2. **Text-only models:** The OBLITERATUS GGUF models have no audio encoder — `Gemma4GgufBackend` hardcodes `supportsAudio = false`. Even if the profile issue were fixed, GGUF Gemma 4 could only do text post-processing, not audio transcription (the app's core use case).

The actual working path is the existing `.litertlm` format, which uses `LlmTranscriptionBackend` with `supportsAudio = true` via `llmManager.generateFromAudio()`. The `.litertlm` variants (GEMMA_4_E2B, GEMMA_4_E4B, GEMMA_3N variants) are already in `ModelDownloader`. Testing E2B quality vs E4B is the actionable next step (TASK-192).
