# Hebrew (he) ASR Scout Report - TASK-551

Date: 2026-09-17. Scope: Hebrew on-device ASR for Anti-Vocale (sherpa-onnx 1.13.8, catalog max 988MB, ~1.5GB arguable for a big win). All metadata gathered from live HF API + model cards; no model files downloaded.

## Context: what Hebrew users get today

The app ships multilingual `sherpa-onnx-whisper-turbo` (openai large-v3-turbo) and the streaming Nemotron 3.5. The official ivrit-ai leaderboard (benchmark.csv, URL below) measures both on Hebrew: base large-v3-turbo = 8.4% WER eval-d1 / 12.8% eval-whatsapp; multilingual nemotron-3.5-asr-streaming-0.6b = 17.1% / 36.5%. So today's Hebrew experience is 12.8% (offline) or an unusable 36.5% (streaming). A dedicated model nearly halves the offline number.

## Ranked recommendations

### 1. ivrit-ai/whisper-large-v3-turbo (the catalog candidate) - NEEDS-CONVERSION

Apache-2.0 source, the reference Hebrew model (their API and the whole Israeli STT ecosystem run on it), 5,000h+ training (Knesset 4700h + crowd 350h), and 988MB in sherpa int8, exactly the catalog cap, same architecture and size class as the app's existing Whisper Turbo entry.

- WER: 6.1% (20250403) or 7.1% (20250513) on WhatsApp-style audio; two independent sources agree on ~7%.
- Files a sherpa load needs: `whisper-encoder.int8.onnx`, `whisper-decoder.int8.onnx`, `tokens.txt`, produced by the standard sherpa-onnx whisper export from the HF checkpoint (community-model-conversion skill path; publish the export under our org, as done for previous community models).
- Integration constraints from the model card: language detection is degraded, must force Hebrew token (the app has `SherpaBackend.forcedLanguage` + the TASK-457 language pinning, so this is a catalog flag, not new code); the translation task is untrained, so the entry is transcription-only; PunctuationPolicy: whisper punctuates natively.
- Open detail: the leaderboard lists two turbo checkpoints (20250403 whatsapp 6.1%, 20250513 whatsapp 7.1% but better eval-d1 5.3%); the plain `whisper-large-v3-turbo` repo is the maintained one (`_20250403_rc0` repos are pinned snapshots). Confirm which revision the export picks during conversion.

### 2. Ibrerhim/sherpa-ivrit-whisper - VALIDATE-TONIGHT (external import only)

Already in sherpa int8 layout with exactly the three roles the app's external Whisper importer keyword-matches (`ivrit-encoder.int8.onnx`, `ivrit-decoder.int8.onnx`, `ivrit-tokens.txt`; ModelFamilySupport.kt WhisperSupport: encoder .onnx + decoder .onnx + tokens .txt). Import via URL from the HF repo tonight, run the device harness, and measure Hebrew quality with zero conversion work.

- It cannot be bundled in the catalog: no license anywhere in the repo (HF default is all-rights-reserved), no README, 0 downloads, unknown maintainer, and the base-checkpoint provenance is unverified (file sizes are consistent with a plain sherpa int8 export of large-v3-turbo).
- Its role is evidence: if device validation confirms ~7% WER behavior, that de-risks the conversion task for candidate 1, which then replaces it with a clean Apache-2.0 export.

### 3. niobures/Fast-Hebrew-ASR (GigaAM-He) - NEEDS-CONVERSION (fast tier, later)

MIT, 220M, measured 4 to 5x faster than ivrit whisper, trained on openly-licensed data (crowd-transcribe-v5 train split + HebDB) with an unusually honest model card (publishes the comparison where it loses). At ~220MB int8 it would be the smallest Hebrew model possible. But WER is 14.7% on WhatsApp audio (2x the turbo fine-tune) and CTC means no punctuation. Only worth a conversion task if we want a "fast Hebrew" tier; otherwise skip.

## Verdicts (one line each)

- ivrit-ai/whisper-large-v3-turbo: VALIDATE via export path; the catalog candidate (Apache-2.0, 988MB int8, 6 to 7% WhatsApp WER, dual-source).
- Ibrerhim/sherpa-ivrit-whisper: VALIDATE-TONIGHT as external import; REJECT for bundling (no license).
- niobures/Fast-Hebrew-ASR: NEEDS-CONVERSION; pursue only for a fast tier (14.7% WER, no punctuation).
- notmax123/nemotron-3.5-asr-hebrew-streaming-0.6b: NEEDS-CONVERSION; REJECT for now (self-reported 17.4% on parliament dev, worse than every whisper option, no WhatsApp evidence).
- ivrit-ai/whisper-large-v3: REJECT (int8 ~1.9GB over cap; marginal quality gain over turbo).
- imvladikon/wav2vec2-xls-r-300m-hebrew: REJECT (2022-era CTC quality, no punctuation; 300m repo also lacks a license tag).
- imvladikon/wav2vec2-large-xlsr-53-hebrew: REJECT (same era, 1B size for worse-than-whisper quality).
- dm15/whisper-small-hebrew, BuzzASR/hebrew, chani-polak/whisper-hebrew-chani: REJECT (no WER evidence, fleurs-only or personal training data).
