### Parakeet TDT v3 SmoothQuant int8 — Long-Audio Fix (NEW)
- **Source:** https://huggingface.co/Olicorne/parakeet-tdt-0.6b-v3-smoothquant-onnx
- **Created:** June 5, 2026
- **Size:** 842 MB encoder (vs stock int8 622 MB, fp16 ~1.2 GB)
- **Languages:** 25 EU langs (same as base Parakeet TDT v3)
- **Format:** ONNX, SmoothQuant int8 encoder + fp16 encoder also included
- **Problem fixed:** Stock int8 Parakeet degrades severely on long audio (40.4% WER on 390s audio). SmoothQuant int8: 11.32% (vs fp16's 10.17%). This is a **73% reduction in long-audio degradation**.
- **How SmoothQuant works:** Pre-quantization smoothing migrates quantization difficulty from activations to weights, making int8 quantization more robust for long sequences.
- **sherpa-onnx compatible:** Uncertain — uses `onnx-asr` library, file layout may differ from csukuangfj's sherpa-onnx packaging. Needs testing.
- **Italian quality assessment:** Same base model as current Parakeet TDT v3. The SmoothQuant fix should improve Italian long-audio quality specifically.
- **Score:** 7.5/10 (Italian quality: 8 — same base + long-audio fix, Size: 7 — 842 MB vs 464 MB stock int8, On-device: 7 — ONNX but needs sherpa-onnx verification, Multilingual: 7 — 25 langs, Maintenance: 6 — community export with detailed benchmarks)
- **Recommendation:** **evaluate** — this is the most actionable short-term improvement for Anti-Vocale. If sherpa-onnx compatible, it's a drop-in replacement that fixes long-voice-message transcription quality. The 842 MB size is acceptable (between Whisper Small 358 MB and Turbo 988 MB).
- **Effort to integrate:** low if sherpa-onnx compatible — just swap encoder file and update config. Medium if repackaging needed.
- **Notes:** Also ships an fp16 encoder (exactly equal to fp32 at half size). The author's benchmark methodology is thorough and the SmoothQuant approach is well-documented. This is a practical quality improvement for the model we already use.

## Landscape Developments

**Nemotron-3.5-ASR Italian quality is confirmed at 4.25% WER on FLEURS** (LangID, 1.12s chunk), matching Anti-Vocale's best current model (Distil IT at ~4.3%). The CoreML export independently validates this at 5.41% on a different chunk size. The model's combination of streaming, 40 languages, auto-detect, punctuation, and competitive Italian quality makes it the strongest candidate to replace or complement the current ASR pipeline. The remaining blocker is integration: sherpa-onnx doesn't support the multilingual variant yet, and the community ONNX exports use custom runtimes (soniqo speech-android SDK or onnx-asr library).

**Parakeet SmoothQuant int8** is a practical, short-term quality fix for the model Anti-Vocale already uses. The stock int8 Parakeet's 40.4% WER on long audio (390s) is a known issue that SmoothQuant reduces to 11.3%. For voice messages that are typically 30-120s, this should meaningfully improve transcription quality. The 842 MB size increase (from 464 MB) is the trade-off.

**llama.cpp Gemma 4 audio** exists but is too poor for ASR. Community testing shows looping output, hallucinations, and extremely slow processing. This confirms that the .litertlm path remains the only viable Gemma 4 audio integration for Anti-Vocale.

**LiteRT-LM MTP drafters** are a meaningful performance improvement — 1.6-2.2x decode speedup for Gemma 4 models. If Anti-Vocale upgrades to v0.13.1, the LLM transcription backend would benefit directly.
