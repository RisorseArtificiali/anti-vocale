## ASR Model Findings

### Olicorne SmoothQuant Parakeet ONNX — Long-Audio Fix (MAJOR NEW FINDING)

- **Source:** https://huggingface.co/Olicorne/parakeet-tdt-0.6b-v3-smoothquant-onnx
- **Architecture:** NVIDIA Parakeet TDT 0.6b v3 (FastConformer-TDT), SmoothQuant int8 encoder
- **Base model:** istupakov/parakeet-tdt-0.6b-v3-onnx (ONNX export)
- **Created:** June 5, 2026 | **Last modified:** June 9, 2026
- **Downloads:** 21
- **Format:** ONNX (istupakov/onnx-asr format, NOT sherpa-onnx format)
- **Languages:** 25 European languages (same as base — it, en, fr, de, es, etc.)
- **License:** CC-BY-4.0
- **Key innovation:** SmoothQuant + static per-channel int8 quantization with per-channel weight folding. The stock int8 encoder uses dynamic per-tensor activation quantization which degrades badly on audio >20–30s. SmoothQuant migrates activation outliers into weights, eliminating this failure mode.
- **Encoder sizes:**
  - Stock int8 (istupakov): 622 MB — **40.40% WER** on 390s clip
  - **SmoothQuant int8 (this): 842 MB — 11.32% WER** on 390s clip
  - fp16: ~600 MB — 10.17% WER on 390s clip (byte-for-byte identical to fp32)
  - fp32: ~1.2 GB — 10.17% WER
- **Per-section results (390s JFK clip, no chunking):**

  | Section | Stock int8 | SmoothQuant int8 | fp16/fp32 |
  |---------|-----------|-----------------|-----------|
  | 0–60s   | 41.4%     | **3.4%**        | 2.6%      |
  | 60–120s | 29.2%     | **3.5%**        | 5.3%      |
  | 120–180s| 39.1%     | **7.0%**        | 3.9%      |
  | 180–240s| 28.2%     | **4.3%**        | 3.4%      |
  | 240–300s| 69.5%     | **46.3%**       | 45.1%     |
  | 300–390s| 42.2%     | **15.9%**       | 13.8%     |

- **FLEURS French validation (held-out):** 4.98% WER (beam 10) / 5.05% (greedy) — confirms multilingual capability preserved
- **Calibration:** 8 bilingual (FR/EN) political speeches, NO labels used, NO Italian-specific data. Pure activation-based calibration.
- **Sherpa-onnx compatibility:** **UNCERTAIN** — The model uses istupakov/onnx-asr file naming (`encoder-model.int8.onnx`, `decoder_joint-model.int8.onnx`, `nemo128.onnx`). sherpa-onnx uses its own packaging convention (`encoder.int8.onnx`, `decoder.int8.onnx`, `joiner.int8.onnx` with `tokens.txt`). The ONNX graphs themselves should be compatible, but the files need repackaging for sherpa-onnx.
- **Score:** 9/10 (Italian quality: 9 — same base model with better int8 numerics, Size: 7 — 842 MB encoder (220 MB larger than stock int8), On-device: 8 — ONNX int8 runs on Android via sherpa-onnx (pending packaging verification), Multilingual: 8 — 25 EU langs preserved, Maintenance: 7 — community project, well-documented)
- **Recommendation:** **EVALUATE — HIGH PRIORITY** — This directly addresses the long-audio quality issue that Anti-Vocale works around with 1s tail padding. If the SmoothQuant encoder is compatible with sherpa-onnx (or can be repackaged), it would be a drop-in upgrade for the existing Parakeet backend with measurable quality improvement on long voice messages. The 220 MB size increase (622→842 MB for encoder) is acceptable within Anti-Vocale's existing model size range.
- **Integration effort:** Low-Medium — If the ONNX file can be renamed/repackaged for sherpa-onnx, it's a direct encoder swap. The decoder/joiner/tokenizer are unchanged from istupakov. Need to verify that sherpa-onnx's Parakeet loader accepts the SmoothQuant encoder without errors.

## Landscape Developments

**SmoothQuant Parakeet encoder** is the most impactful finding this cycle. The long-audio int8 degradation is a well-known problem in the Parakeet ecosystem — the stock int8 encoder's dynamic per-tensor quantization can't represent wide activation distributions on long sequences. Olicorne's SmoothQuant approach (per-channel static quantization with outlier migration) tracks fp16 quality at half the RAM. This validates that the quality issue is purely a quantization artifact, not an architectural limitation. For Anti-Vocale, which uses 1s tail padding to work around this very issue, a SmoothQuant encoder could simultaneously improve quality and simplify the inference pipeline.

**Parakeet in HuggingFace Transformers** (`eustlb/parakeet-rnnt-0.6b`) signals growing ecosystem adoption. When NVIDIA's own Parakeet models get first-party HuggingFace support with native timestamping and fine-tuning, it suggests the architecture will remain well-supported long-term.
