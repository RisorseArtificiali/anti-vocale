# Model Scout Report -- 2026-08-20

Scope: parakeet + sherpa-onnx frameworks. Single question: is there a more recent Parakeet TDT export (or successor) that fixes the long-input attention position-bias limit (~400s / 5000 frames)?

## Executive Summary

No drop-in replacement or upstream fix exists. The `max_position_embeddings: 5000` is an architectural constant in NVIDIA's `nvidia/parakeet-tdt-0.6b-v3` checkpoint config. Every ONNX export derived from it inherits the 5000-frame relative-position-bias table in the ONNX graph. No newer Parakeet TDT variant has been released. sherpa-onnx's offline transducer path feeds the entire encoder at once with no chunking, and v1.13.6 (2026-08-18) contains no relevant changes. The mitigation path is application-level audio segmentation, not a model or framework swap.

## Question 3: Is the 5000-frame cap inherent to NeMo's RelPositionalEncoding?

**Yes.**

Evidence:
1. `nvidia/parakeet-tdt-0.6b-v3/config.json` line 28: `"max_position_embeddings": 5000`
2. `nvidia/parakeet-ctc-1.1b/config.json`: also `"max_position_embeddings": 5000`
3. The OpenVoiceOS 1.1b ONNX export also uses this architecture.
4. The istupakov export calls NeMo's `model.export()` which internally uses the model's stored config to build the relative position bias lookup table. The table has shape `[2*max_position_embeddings-1, num_heads]` = `[9999, 8]`. This is a constant tensor embedded in the ONNX encoder graph.
5. At 12.5 fps (16kHz input, subsampling factor 8), 5000 frames = 400 seconds exactly.

The BroadcastIterator error at `/layers.0/self_attn/Add_2` occurs because the ONNX graph hardcodes the bias table dimension to 9999 (= 2*5000-1), and when the encoder produces more than 5000 frames, the Add node cannot broadcast `[9999, 8]` against `[N, 8]` where N > 9999.

**Any ONNX export of this model family will have this limitation.** The only way to raise it is to:
- Re-export from NeMo with a modified `max_position_embeddings` value (requires patching the NeMo checkpoint config before export, which may or may not produce valid weights for positions beyond 5000), OR
- Edit the ONNX graph to resize the constant tensor (risky; the attention weights were trained with max 5000 positions)

## Root Cause Summary

```
Audio duration (s)  |  Frames at 12.5 fps  |  Position bias table size  |  Status
--------------------|---------------------|---------------------------|--------
< 400              |  < 5000             |  9999 (2*5000-1)          |  OK
= 400              |  = 5000             |  9999                      |  Boundary
> 400              |  > 5000             |  Frames > 9999/2          |  BROADCAST ERROR
```

The cap is at three levels, all fixed:
1. **NVIDIA model config**: `max_position_embeddings: 5000` in `config.json`
2. **ONNX graph**: constant tensor of shape `[9999, 8]` baked into the encoder
3. **sherpa-onnx**: offline path has no chunking/segmentation

## Prioritized Recommendations

| # | Action | Impact | Effort | Risk |
|---|--------|--------|--------|------|
| 1 | Application-level audio segmentation (split >400s audio into overlapping chunks before feeding to Parakeet) | High (fixes the crash) | Medium | Low (quality at chunk boundaries needs validation) |
| 2 | File a sherpa-onnx issue requesting offline-transducer chunking for NeMo models with position-bias limits | Medium (upstream awareness) | Low | None |
