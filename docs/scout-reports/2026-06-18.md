# Model Scout Report — 2026-06-18

## Executive Summary

**A quiet 3-day delta dominated by carryover.** No new sherpa-onnx release (v1.13.3 from 06-15 remains latest), no new sherpa-onnx-native Italian model, and no movement on the Italian Whisper fine-tune front (still dead since March).

The most important finding is a **process gap, not a model**: the top recommendations from the 06-15 report — upgrade sherpa-onnx v1.13.2 → v1.13.3, integrate the pantinor SmoothQuant Parakeet, and swap Nemotron fp32 → int8 — are all **still pending**. The gate is cleared; the work just hasn't shipped.

Two new models worth noting but neither actionable today: `shahrukhx01/parakeet-tdt-0.6b-v3-fp16-onnx` (created today — same model Anti-Vocale already runs, but fp16 in raw ONNX, wrong precision/format for mobile) and `jinhwan000/qwen3-asr-0.6b-onnx` (a genuinely small real-int4 Qwen3 export, but a custom-inference-loop PoC, not a sherpa-onnx drop-in). The Nemotron 3.5 streaming ecosystem continues to accelerate (canonical source at 7,195 downloads; CSTR GGUF nearly doubled to 657 in 3 days) but almost entirely outside sherpa-onnx.

**Baseline correction:** The in-repo inventory (`references/model-inventory.md`) predates HEAD. The app now ships an **`OmnilingualAsrBackend`** (Meta Omnilingual ASR v2, CTC, 1600+ languages) added at commit `33f8885`, alongside Parakeet/Whisper/Qwen3/Nemotron. It uses `OfflineOmnilingualAsrCtcModelConfig` (encoder + tokens only), positioned as an exotic-language fallback. No external model change — flagged for inventory accuracy.

- **Source:** https://huggingface.co/shahrukhx01/parakeet-tdt-0.6b-v3-fp16-onnx
- **Created:** June 18, 2026 (today, 07:53 UTC)

- **License:** cc-by-4.0
- **sherpa-onnx compatible:** No — would require re-splitting + sherpa repackaging
- **Italian quality assessment:** Same weights/model as current Parakeet v3 int8 (~4.3% WER clean FLEURS per existing benchmarks). fp16 ≠ better than the int8 we ship.
- **Score:** 4/10 (high Italian quality ×3, but fp16 is the wrong precision for ARM NEON mobile inference — ~2× the size of int8 with typically *worse* CPU latency — and it's not in sherpa-onnx format)
- **Recommendation:** **WATCH** (effectively skip). This is the same model Anti-Vocale already runs. fp16 is a desktop/server precision; on Android ARM64, int8 dominates. Useful only as a higher-precision reference if a future int8 quality regression needs diagnosing.
- **Effort to integrate:** High (re-split + repack to sherpa-onnx), for negative mobile benefit.
- **Notes:** Ecosystem signal that Parakeet v3 ONNX exports are proliferating, but adds nothing over the in-tree int8 model.

### jinhwan000/qwen3-asr-0.6b-onnx — NEW-ish, real int4 (watch)
- **Source:** https://huggingface.co/jinhwan000/qwen3-asr-0.6b-onnx
- **Updated:** June 15, 2026 (99 downloads)
- **Size:** ~150–200 MB estimate (real int4 encoder via MatMulNBits + int4 decoder)
- **Languages:** Qwen3-ASR's 52 languages incl. **Italian**
- **Format:** ONNX, `onnxruntime` library — **real int4** weights (MatMulNBits), with the autoregressive decoder split into `decoder_init` / `decoder_prefill` / `decoder_step` graphs + external KV-cache + precomputed mel DSP constants
- **License:** Apache-2.0
- **sherpa-onnx compatible:** No — generic onnxruntime PoC requiring a custom inference loop (manual chat-scaffold prompt building, hand-rolled log-mel via `hann_400.f32`/`mel_filters.f32`, autoregressive decode). Not a sherpa-onnx drop-in.
- **Italian quality assessment:** Not independently benchmarked; claims parity with `Qwen/Qwen3-ASR-0.6B` reference (which Anti-Vocale already ships via csukuangfj's sherpa int8). Italian WER ~12.2% in prior 4-model benchmark — Qwen3 is already the weakest of the four for Italian.
- **Score:** 5/10 (size efficiency ×2 is the draw — ~half of csukuangfj's ~300 MB int8; but Qwen3 Italian quality is mediocre, and integration is a full custom decoder loop, not sherpa bindings)
- **Recommendation:** **WATCH.** The "real int4" encoder is the interesting part (genuinely small). Worth revisiting only if Anti-Vocale ever needs a <200 MB fallback and is willing to maintain a custom onnxruntime inference path. sherpa-onnx has no Qwen3 int4 binding today.
- **Effort to integrate:** High (custom inference loop, manual mel frontend, no JNI/sherpa integration).
- **Notes:** Naming was corrected on 2026-06-03 — `encoder.int4.onnx` is now the real int4 (earlier revisions mislabeled fp32 as int4). Re-download if cached.

## Landscape Developments

- **QNN/NPU maturation for Parakeet:** sherpa-onnx is actively building out Qualcomm Hexagon (QNN/HTP) support for Parakeet CTC (two commits today, #3686/#3688). This is the Snapdragon-NPU acceleration story — not Anti-Vocale's CPU path, but worth watching: if a future Anti-Vocale target device has a capable NPU, this could be a major latency win. The `trsdn/parakeet-tdt-0.6b-v3-htp-int8-8s` model (40 EU langs incl. Italian) already targets this path.
- **Nemotron 3.5 streaming is the ecosystem's gravitational center.** Canonical source at 7K+ downloads and a fast-multiplying set of GGUF/CoreML/NeMo mirrors confirm it's the current "model to port everywhere." For Anti-Vocale the only Android CPU entry point remains csukuangfj2's sherpa int8.
- **int4 quantization is proliferating but unvalidated on Android:** jinhwan000 (Qwen3, real int4), jeffpeng3 (Nemotron int4 dynamic), trsdn (Parakeet HTP int4). None are sherpa-onnx drop-ins yet. The sub-200 MB ASR model is becoming feasible but the tooling isn't there for Anti-Vocale's runtime.
