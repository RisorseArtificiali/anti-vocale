The E2B variant (2B effective, ~4.6B total params) is now available in multiple GGUF conversions. Uses the same `gemma4` architecture already supported by our llama-bro v1.3.0-gemma4 fork.

- **Size:** Q4_K_M estimated ~2.5-2.8GB (imatrix-optimized)
- **Languages:** Same multilingual capability as Gemma 4 (140+)
- **Last updated:** 2026-04-19
- **Format:** GGUF, imatrix-optimized quants (IQ1_M through Q6_K)
- **llama-bro compatible:** Yes — same `gemma4` architecture
- **Score:** 7.5/10 (quality uncertain at 2B 3/5, size excellent 5/5, feasible 5/5, multilingual 5/5, maintained 3/5)
- **Recommendation:** **evaluate** — benchmark text generation quality against current E4B OBLITERATED. If quality is acceptable for transcription post-processing, the ~50% memory reduction is significant.
- **Effort to integrate:** Low — same architecture, swap GGUF file in llama-bro
- **Notes:** 7,071 downloads. Same OBLITERATED lineage as current model. imatrix quants provide better quality-per-bit than standard quants.

## Landscape Developments

### NVIDIA unified streaming+offline architecture
NVIDIA's `parakeet-unified-en-0.6b` demonstrates a single model handling both streaming and offline ASR (1.63% offline WER, 1.78% streaming on LibriSpeech). If this architecture gets a multilingual version, it could replace our current approach of separate partial/final transcription paths. Worth monitoring.

### Gemma 4 E2B expands the on-device LLM option space
The E2B variant (2B effective params) creates a new option between "no LLM" and the current 4.9GB E4B. At ~2.5GB Q4_K_M, it could fit on devices where the E4B is too large, or coexist with larger ASR models. The quality tradeoff (2B vs 4B) needs benchmarking for transcription post-processing tasks.

### SenseVoice still no Italian
SenseVoice Small ONNX export appeared (230MB, Chinese/English/Japanese/Korean/Cantonese). Still no Italian or European language support. The size is attractive but the language coverage is wrong for our use case.
