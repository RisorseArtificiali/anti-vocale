# Scout report: LiteRT-LM 0.18.0 targeted check (maintainer request)

Date: 2026-10-08. Scope: frameworks, LiteRT-LM only. Trigger: the maintainer
recalled "a bug in the new version that suggests it should not be used" and
asked for a targeted verification before any bump consideration.

Current pin: `litertlm = "0.17.1"` (gradle/libs.versions.toml; shipped in
production since September; the 0.17.1 POM pulling coroutines 1.11.0 fixed
the first-audio-turn close$default crash, GH #3334 follow-up).

## The new release: v0.18.0 (2026-10-06)

Headline features (release notes, GH #3869): EmbeddingGemma 2 (text/vision/
audio embeddings, Matryoshka truncation), `litert-lm import` fast imports,
OpenAI-compatible `/v1/embeddings` serve endpoint, ModelInfo/describe
introspection API, dynamic KV-cache growth on NPU, attention-mask pruning on
GPU. Nothing in the notes targets our path (Gemma audio transcription via
`sendMessageAsync` on Android CPU).

## Bug landscape at release time (all verified open issues, 2026-10-08)

The maintainer's recollection is CORRECT in substance: the 0.18.0 window
carries multiple open defects, two of them Android-packaging-level:

1. **GH #3891 (open, 2026-10-08): `libGemmaModelConstraintProvider.so` is not
   16 KB page-aligned.** Android makes 16 KB alignment a hard requirement for
   store updates from Jan 2027, and the issue author flags the problem may
   extend to other prebuilt Android libs in the release. This is a "do not
   adopt for shipping" defect on its own timeline, independent of anything we
   care about functionally. (The sibling macOS dylib failure is #3890.)
2. **GH #3867 (open): v0.17.x Android WebGPU SIGSEGV on Adreno 750** (Qualcomm
   shader compiler crash in wgpuDeviceCreateComputePipeline; v0.14.0's Dawn
   binary worked). Labeled v0.17.x, still open at 0.18.0: any GPU-delegate
   ambitions stay blocked.
3. **GH #3862 (open): deleting a GPU engine leaks ~2 GB graphics memory on
   Android** when OpenCL cannot load; fix exists in LiteRT core
   (9c8ae4e0) but is NOT in any LiteRT-LM release.
4. **GH #3851 (open): Gemma 4 E2B nonverbal-audio omission and image
   chronology errors on Android 0.17.1**, with a careful synthetic
   reproduction (Galaxy S25, API 36, our exact Maven artifact hash). Our
   runtime version and model are the reproduction environment; relevant if
   users report missing nonverbal sounds in Gemma transcripts. Unresolved
   upstream (not established as a LiteRT-LM defect).
5. **GH #3879 (open): corrupted Korean output on Galaxy Z Flip5 GPU**,
   FLOAT32+separate-cache workaround; GPU again.
6. **GH #3852/#3850 (open): KV-cache cross-talk in interleaved Metal
   conversations; iOS audioFile() null returns.** Not our platform, but they
   show the audio path is under active repair around the release.

Several audio-path fixes DID land in the 0.18.0 code (closed PRs): UTF-8
byte-fallback detokenization (#3883), streaming-encoder context reset (#3847
track), ring-buffer EOF zero-padding (#3830), Gemma 4 audio-encoder LoRA
input names (#3868), ASR/TTS session unification (#3874/#3880). The audio
stack is being reworked mid-flight; the release notes do not mention any of
it (embedding-model release).

## Verdict

**Stay on 0.17.1. Do not bump to 0.18.0.** Three concrete reasons:

- The 16 KB alignment defect (#3891) is a shipping-blocker class issue on
  Android with a known deadline pressure; adopting it now would bake the
  defect into our AAB.
- Nothing in 0.18.0 benefits our path: the release is an embedding-model
  release; our Gemma transcription path is untouched by the notes, and the
  audio-path churn that did land is unadvertised and mid-rework.
- The GPU-track defects (#3867, #3862, #3879) block any future delegate work
  we might have wanted to trial.

Watch: a 0.18.1 with 16 KB alignment fixed would re-open the question, though
the value proposition for us remains ~zero until an audio/transcription-
relevant feature ships. #3851 is the one to watch for our Gemma quality
reports regardless of version.

No action taken; pin stays `0.17.1`. sherpa-onnx v1.13.8 remains latest
(checked 2026-10-08).
