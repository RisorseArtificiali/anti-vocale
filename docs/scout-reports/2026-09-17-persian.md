# TASK-550: Persian (fa) ASR model scout, 2026-09-17

Context: Iran is the 6th install market (18 installs) with zero coverage. Whisper's 99-language set and Parakeet's 25-language set both exclude Persian, so only a dedicated fine-tune can cover it. Baseline constraints: sherpa-onnx 1.13.8, under ~1GB, redistribution-friendly license, competitive WER with a source.

## Headline finding

The Shenava-1 family (author Reza2kn, mirrors at PersianML, sherpa exports also mirrored by mah92) is a Persian ASR project built around `nvidia/stt_fa_fastconformer_hybrid_large`, published in June 2026 with official sherpa-onnx deployment bundles, Apache-2.0 end to end, and author-reported evals. It is ready to validate tonight; nothing needs conversion.

- `Reza2kn/Shenava-Koochik-v1.0` (114M params, FastConformer hybrid RNNT/CTC, Apache-2.0): visualears-golden-6669 WER 7.49%, FLEURS-fa WER 10.64% (card, "double-benchmark ITN/Persian-digit normalization" convention).
- `Reza2kn/Shenava-Rizeh-v1.0` (32M, distilled): golden 12.11%, FLEURS-fa 14.45%.
- `Reza2kn/Shenava-Rizeh-Pizeh-v1.0` (6.9M): golden 24.55%, FLEURS-fa 26.95% (too weak for flagship; interesting ultra-small tier only).
- Official bundles: `Reza2kn/Shenava-Koochik-v1.0-sherpa-onnx` (CTC, fp32 458.8MB), `Reza2kn/Shenava-Rizeh-v1.0-sherpa-onnx`, `Reza2kn/Shenava-Rizeh-Pizeh-v1.0-sherpa-onnx`, and `Reza2kn/Shenava-Koochik-v1.5-RNNT-sherpa-onnx` (transducer with int8, ~137MB total). All tagged license apache-2.0, library sherpa-onnx.

The v1.5 RNNT repo is the best single target: complete sherpa transducer layout (encoder/decoder/joiner + tokens), int8 alongside fp32, loads with `OfflineRecognizer.from_transducer(..., model_type="nemo_transducer")`, which is the same sherpa path as our built-in Parakeet/GigaAM entries. The int8 set is 131.3 + 4.0 + 1.4 = ~137MB, smaller than Whisper Small (358MB). Card claims int8 "decoded byte-identically to fp32" on their Persian clips. RNNT head WER 9.50 on golden-6669 (model-index); the CTC head at 8.12% is their record holder.

Documented gotchas (from the official cards, verified read this session):
1. Both exports train with `normalize=NA`: the ONNX metadata sets `normalize_type=""` so sherpa-onnx must NOT re-normalize. sherpa 1.13.8 reads this from model metadata; confirm the empty value is honored in our pinned runtime during validation ("otherwise the output is garbage").
2. The RNNT decoder is an LSTM prediction network (not the stateless context-N style of Parakeet); sherpa's nemo_transducer path supports it and their `export-rnnt-sherpa.py` is shipped for reproduction.
3. Offline bundles use full-context att_context [-1,-1]; streaming cache-aware graphs exist only in the mah92 mirrors.
4. Numbers are spoken-form; `persian_itn.py` (in the CTC bundle) converts to Persian digits. Optional post-processing we would skip initially.
5. Trust signal is thin: all Shenava repos are new (created 2026-06 onward, downloads 0, likes 1-2). Evals are author-reported on author-held test sets (visualears-golden-6669) plus FLEURS-fa; verify with our own harness on FLEURS fa / Common Voice fa before catalog listing.
6. License conflict note: mah92's mirrors of the same weights are tagged cc-by-nc-4.0 while the canonical Reza2kn repos are Apache-2.0. Use the official repos (or quantize from the Apache source ourselves); do not redistribute mah92's mirrors.

Note on the app side (verified in source this session): the external-models platform ALREADY supports both load paths today. `ModelFamilySupport.kt` maps `nemo_ctc` to `OfflineNemoEncDecCtcModelConfig` (CTC family, encoder + tokens only, modelType required) and `nemo_transducer` for the TRANSDUCER family; the CTC import UI defaults to `nemo_ctc` (`ModelTab.kt:1133`). So Persian support is reachable without new engine code: a catalog entry (Parakeet-style bundled) or even a community-catalog entry pointing at the HF repos.

## Top 3 ranked

1. Reza2kn/Shenava-Koochik-v1.5-RNNT-sherpa-onnx. Files for a sherpa transducer load: `encoder.int8.onnx` (131.3MB), `decoder.int8.onnx` (4.0MB), `joiner.int8.onnx` (1.4MB), `tokens.txt` (SentencePiece BPE-1024). fp32 set also in repo. Loads exactly like GigaAM/Parakeet (`from_transducer`, `model_type="nemo_transducer"`). Apache-2.0. ~137MB total.
2. Reza2kn/Shenava-Koochik-v1.0-sherpa-onnx. Files: `model.onnx` (458.8MB) + `tokens.txt` (1025 tokens) + optional `hotwords_fa.txt`/`persian_itn.py`. `from_nemo_ctc`. Slightly better WER head per their table (8.12% vs 9.50% on golden) but 3.3x larger than RNNT int8 and fp32 only.
3. Reza2kn/Shenava-Rizeh-v1.0-sherpa-onnx. The 32M small tier (FLEURS-fa 14.45%) as a "Persian lite" option; mah92's int8/streaming mirrors of it exist but carry the cc-by-nc-4.0 tag.

Sibling sherpa repos to keep in catalog notes: the three CTC bundles above, the RNNT bundle, and the mah92 streaming mirrors (license tag conflict documented).

## Verdicts

- Reza2kn/Shenava-Koochik-v1.5-RNNT-sherpa-onnx: VALIDATE-TONIGHT (download the 4 int8 files, load in eval/.venv sherpa-onnx 1.13.8, decode 2-3 fa clips, then FLEURS/CV fa WER with our harness).
- Reza2kn/Shenava-Koochik-v1.0-sherpa-onnx: VALIDATE-TONIGHT (2 files, from_nemo_ctc; check the empty normalize_type metadata behavior on 1.13.8 explicitly).
- Reza2kn/Shenava-Rizeh-v1.0-sherpa-onnx: VALIDATE-TONIGHT (same shape as number 2; only if the small tier is wanted).
- Peacockery/parakeet-ctc-109m-farsi: NEEDS-CONVERSION (.nemo export via sherpa scripts; honest card, decent fallback benchmark).
- OpenVoiceOS/nvidia fa fastconformer: NEEDS-CONVERSION (OVOS layout reshaping; Shenava is a fine-tune of this same base and already sherpa-ready, so low priority).
- Whisper-large fa fine-tunes (onnx-community MIT one included): REJECT for now (size over budget without proof of a quality win; WER unverified).
- AmirMohseni and other whisper fine-tunes: NEEDS-CONVERSION (only worth revisiting if Shenava fails validation; whisper-small-persian is the size-compatible one).
- jonatasgrosman/m3hrdadfi wav2vec2 XLSR: REJECT (2021-era, superseded, no size or quality advantage).
- MohammadGholizadeh/parakeet-ctc-1.1b-persian.nemo: REJECT (no measured WER, author states training incomplete, over budget).
- Reza2kn/canary-180m-persian: REJECT (WER >100%, research smoke checkpoints).
- Shenava-Rizeh-Pizeh 6.9M: REJECT as flagship (FLEURS 26.95%).
- mah92/whisper-tiny-fa-sherpa-onnx: REJECT (tiny-class quality, no license tag, no eval).
