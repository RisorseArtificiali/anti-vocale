## Executive Summary

Three findings clear the action bar, none is a sherpa drop-in for the Italian default today. (1) `nvidia/canary-1b-v2` was never assessed by any previous scout despite being the strongest measured Italian WER in our size class (FLEURS it_it 3.07, self-reported) and having a sherpa-layout int8 export already on HF; it is evaluable on the existing desktop harness for near-zero cost. (2) `litert-community/VibeVoice-ASR-BitNet` is the first audio-input `.litertlm` ASR model (1.98GB, MIT, Italian-tagged, measured on a Galaxy S26), reachable through the runtime we already ship, but it requires a litertlm-android bump past a known-crash version (issue #3334 still open, verified). (3) Meta Omnilingual ASR v2 gained sherpa conversions at 197 to 247MB for the 300M tier; Italian coverage is claimed via the 1600-language set but unverified. Frameworks: sherpa 1.13.8 remains the latest release (verified); litertlm-android 0.17.0 exists; llama-bro is dormant on both sides. No Italian-specific ASR development landed in the window.

## ASR Model Findings

### nvidia/canary-1b-v2 (sherpa int8 export exists; never previously tracked)
- **Source:** https://huggingface.co/nvidia/canary-1b-v2 (base, lastModified 2026-08-31, card edit; file set unchanged) ; sherpa-layout int8: https://huggingface.co/Sarphix/canary-1b-v2-sherpa-onnx-int8 (created 2026-07-11) ; second export: https://huggingface.co/YaroslavGor/sherpa-onnx-nemo-canary-1b-v2-int (2026-07-09) ; Optimum-layout alternative: https://huggingface.co/istupakov/canary-1b-v2-onnx (2026-02-17)
- **Size:** Sarphix int8 tar.bz2 1144.9 MB (encoder.int8 857.6 MB + decoder.int8 558.7 MB + tokens.txt); note the int8 decoder is larger than the fp16 decoder (338.3 MB), unexplained by the uploader
- **Languages:** 25 European including Italian (HF tags, verified from API)
- **Format:** ONNX int8, sherpa `from_nemo_canary` layout; uploader verified decode on sherpa-onnx 1.13.4 Python (German and English smoke tests only; Italian NOT smoke-tested, single-source)
- **sherpa-onnx compatible:** yes, same model family as the existing CANARY external import path (128 mel bins, 10s chunk cap family rules apply)
- **Italian quality:** FLEURS it_it WER 3.07 (NVIDIA model card model-index, self-reported, unverified flag; for scale: de 4.4, en 4.5, fr 5.02). Our Parakeet reference is 4.3% clean / ~10% real WhatsApp audio on a different test set; numbers are NOT directly comparable. Voice-message WER unknown until we run the harness.
- **Score:** composite 3.6/5 (Italian 4, size 3, feasibility 3, multilingual 5, maintenance 3)
- **Recommendation:** evaluate (desktop harness first)
- **Effort:** low for the eval (sherpa Python 1.13.8 pinned in `eval/.venv` supports `from_nemo_canary`); medium for integration (community-catalog entry + sha256 pin + device verify; CANARY family plumbing already exists)
- **Notes:** the base model is ASR + translation (It->En BLEU 25.57 in card metrics); ASR-only usage needs the language option pinned, same mechanism the Canary Flash entries use. CC-BY-4.0. 1.1GB exceeds the current catalog max (Whisper Turbo 988MB) by ~16%, same class.

### litert-community/VibeVoice-ASR-BitNet (first audio-in .litertlm ASR)
- **Source:** https://huggingface.co/litert-community/VibeVoice-ASR-BitNet (created 2026-09-04, verified via blobs API; base https://huggingface.co/microsoft/VibeVoice-ASR-BitNet, 2026-07-24)
- **Size:** single `VibeVoice-ASR-BitNet.litertlm` 1983.0 MB (verified: 1,983,019,248 bytes); internal split per card: audio encoder 951 MB, prefill/decode 793 MB, embedder 237 MB
- **Languages:** en, zh, fr, it, ko, pt, vi (card tags, verified); Microsoft README says "and more"
- **Format:** `.litertlm`; BitNet b1.58 ternary as int4 blockwise-128 + int8 embedding; audio encoder int8; 30s window with per-chunk context reset
- **sherpa-onnx compatible:** no; runs on LiteRT-LM, the runtime the LLM path already ships. Runtime version is the crux: card measurements use LiteRT-LM 0.16.1; app pins 0.13.1; whether 0.13.1 loads an audio-in bundle is NOT_FOUND
- **Italian quality:** NOT_FOUND (no Italian benchmark exists; English LibriSpeech dev-clean 20 clips: WER 3.12% on Galaxy S26 CPU, RTF 0.24, peak RAM 3.2GB; technical report arXiv:2607.21075 claims 1.6-2.3x faster than whisper.cpp at ~1.6GB with modest degradation vs fp16)
- **Score:** composite 3.0/5 (Italian 3, size 4, feasibility 2, multilingual 2, maintenance 4)
- **Recommendation:** evaluate, sequenced behind the runtime question
- **Effort:** high (litertlm-android bump with device testing + prompt change: best WER needs a duration sentence in the prompt, 3.57% without; RAM budget check on mid-range)
- **Notes:** BLOCKED on litertlm-android upgrade: 0.16.1 crashes on device (SendChannel.close$default, our exp/ branch experience; upstream issue #3334 still OPEN, verified 2026-09-16). 0.17.0 does not mention a fix. This model competes with the Gemma transcription pass at ~40% of its size, not with the sherpa catalog.
- **Dual-source:** independently found by both the ASR and LLM collectors with consistent numbers.
