## ASR Model Findings

### litert-community/parakeet-tdt-0.6b-v3 (TFLite, int8, SoC-specific)
- **Source:** https://huggingface.co/litert-community/parakeet-tdt-0.6b-v3
- **Size:** 586 MB (int8), f32 variants also available (~1.1GB estimated)
- **Languages:** 25 EU languages including Italian (same base model as our Parakeet TDT 0.6b v3)
- **Last updated:** 2026-05-08
- **Format:** TFLite (int8 and f32, stateful and non-stateful variants)
- **sherpa-onnx compatible:** No — TFLite format, not ONNX. Would require TFLite runtime integration.
- **Italian quality assessment:** Same base model as our existing Parakeet TDT 0.6b v3 int8 — identical transcription quality
- **Score:** 5.5/10 (same quality 4/5, larger than ONNX int8 3/5, new format 4/5, multilingual 4/5, Google-backed 4/5)
- **Recommendation:** **evaluate** — This resolves our watch-list item "LiteRT TFLite int8 variants." The int8 TFLite is 122MB larger than our ONNX int8 (586 vs 464MB) but enables NPU acceleration on Qualcomm/MediaTek SoCs. Includes Qualcomm builds for SM8450 through SM8850 (our device is Snapdragon-based). The stateful variant could enable true streaming.
- **Effort to integrate:** High — requires adding TFLite inference runtime alongside sherpa-onnx. Would need a new `TfliteTranscriptionBackend`, model download logic, and SoC detection to select the right variant. Not trivial.
- **Notes:** 604 downloads. 45 files total: generic int8/f32 + 14 SoC-specific f32 builds (7 Qualcomm, 7 MediaTek) + matching stateful variants. The "5s" in the filename suggests 5-second chunk processing. If NPU acceleration provides meaningful speedup, this could improve real-time factor on supported devices.

## Landscape Developments

### Parakeet TDT v3 TFLite ecosystem maturing
Google's litert-community now hosts Parakeet TDT v3 in TFLite with both int8 (586MB) and f32 variants, plus SoC-specific builds for 7 Qualcomm and 7 MediaTek chipsets. This is the same model we use via sherpa-onnx ONNX, but in TFLite format enabling NPU-accelerated inference. The Argmax ParakeetKit (mentioned in the 2026-05-04 report) uses a similar approach. The ecosystem is consolidating around two inference paths for Parakeet on Android: ONNX via sherpa-onnx (our current path) and TFLite via LiteRT/NPU (emerging path).

### Gemma 4 Multi-token Prediction breaks new ground
LiteRT-LM v0.11.0's MTP feature claims >2x faster decode on mobile GPUs with zero quality degradation for Gemma 4. This is significant for our Gemma 4 audio transcription path — if the decode speedup applies to the audio transcription workflow (not just text generation), it would substantially improve latency. Google's blog post links to documentation that may clarify whether MTP works with audio input.

### Qwen3-ASR 1.7B ecosystem expanding
Multiple 1.7B Qwen3-ASR variants appeared (MLX, ONNX, fine-tunes) but all are English-only or limited-language. No Italian-specific 1.7B fine-tunes. The 0.6B variant we already use remains the only size with Italian support and ONNX export.
