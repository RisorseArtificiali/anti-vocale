## Question 1: Finnish ASR

### a) The "mozilla turbo-ft" artifact, and the stale hold

The 2026-10-21 report line "mozilla turbo-ft, NO WER" refers to `mozilla-ai/whisper-large-v3-turbo-fi`, first identified in the 2026-10-06 report. The `mozilla` org itself has zero whisper models on HF (API `author=mozilla&search=whisper` returns empty, checked 2026-10-24); the fine-tunes live under the **mozilla-ai** org (the speech-to-text-finetune blueprint, https://github.com/mozilla-ai/speech-to-text-finetune).

State of the card today (https://huggingface.co/mozilla-ai/whisper-large-v3-turbo-fi, 21 downloads):

- Trained on 2093 Common Voice fi train samples from cv-corpus-22.0-2025-06-20. Apache-2.0.
- **WER now published**: normalized 11.972 on 1806 CV fi test samples (baseline whisper-large-v3-turbo on the same set: 16.576). CER 2.255 vs 3.808 baseline.
- No FLEURS number on the card, so the CV-fine-tune generalization risk (BlasBench, arXiv 2604.10736, flagged 2026-10-06) remains untested for this specific artifact.

The BlasBench trap is no longer hypothetical for fi: `BuzzASR/finnish` (whisper-large-v3 full fine-tune on FLEURS+CV25, EMNLP 2026 Findings paper, arXiv 2609.09554) publishes numbers showing their own fine-tune WORSE than the zero-shot base on FLEURS (CER 5.77 vs 2.12 zero-shot; WER 24.11 on FLEURS). Source: https://huggingface.co/BuzzASR/finnish . This is the strongest available evidence that small-data CV fine-tunes for fi can and do generalize badly; exclude BuzzASR/finnish from candidacy.

Our harness already has the right tool: `eval/fleurs_bench.py` (born from the TASK-860/861 campaign) takes `--langs fi_fi` and runs any sherpa model on disk or any community-catalog entry (`--entry ...orukeet.json`), jiwer-normalized WER, CI-able. Concrete options, all numbers read 2026-10-24:

### c) New sherpa-importable fi since 2026-10-21

Nothing sherpa-native appeared: `search=sherpa+finnish` returns empty; the csukuangfj ASR-tagged feed shows nothing new (newest touches 2025-12-25, one 2026-06-11 repo touch). The window's new fi artifacts are all non-sherpa runtimes: `cerkku/whisper-large-finnish-v3-ggml` (ggml, 10-08), `luweigen/whisper-large-finnish-v3-android` (ggml + Qualcomm QNN encoder for whisper.cpp, 10-19), `XDcobra/wav2vec2-large-xlsr-53-finnish-ONNX` (plain wav2vec2 ONNX, 10-07).

The structural news is the **canary-1b-v2 to sherpa-onnx conversion path now exists and is documented**, which unlocks the whole 25-language canary-1b-v2 family (fi included) for our CANARY external family:

- `bnoordhuis/canary-1b-v2-sherpa-onnx-nl-int8`: int8 encoder 1,161,643,089 bytes + decoder 223,741,759 bytes + tokens.txt, in the layout of sherpa's offline Canary recognizer (`OfflineRecognizer.from_nemo_canary`). Verified on Android (Moto g75) with Dutch FLEURS clips at 6.9 WER; export adapted from sherpa-onnx's Canary-180M.flash script (tag v1.13.8), reproducible to the same SHA-256. The export script itself is NOT yet public ("TODO: link to the public export script once it's published"). https://huggingface.co/bnoordhuis/canary-1b-v2-sherpa-onnx-nl-int8
- Runtime prerequisite: sherpa-onnx 1.13.8 and earlier silently fall back to English for any Canary language outside en/es/de/fr (issue #3961), fixed by PR #3962 (lang2id derived from the model vocab, "warn instead of silently falling back"). **Our pin is already v2.0.0, which contains the fix**, so a fi Canary entry would work with no further runtime bump. Sources: https://github.com/k2-fsa/sherpa-onnx/issues/3961 , https://github.com/k2-fsa/sherpa-onnx/pull/3962 , release notes of v2.0.0 (2026-10-23).

### Candidate cards (fi)

### The one real finding: Nawah-ASR (pan-Arabic, not Egyptian-specific)

`oddadmix/Nawah-ASR-60M-Max-Arabic` (2026-10-06, 58 downloads) + `oddadmix/Nawah-ASR-60M-Max-Arabic-ONNX` (2026-10-10, 90 downloads). Same author as our dialectal v1/v2 lineage (their dialectal v2 models are Apache-2.0; Nawah declares NO license on either repo, and no LICENSE file exists in the tree, checked 2026-10-24).

- Architecture: 62.7M-param Parakeet-style TDT (FastConformer encoder 17L/384, 2-layer LSTM predictor, additive joiner, 1024-unit BPE, durations 0-4), trained from scratch on 8,723h Arabic, single RTX 5090.
- Quality (their card, scored with the Open Universal Arabic ASR Leaderboard's own eval.py): 6-set average 29.86 WER / 13.13 CER, rank 4 of 38, ahead of whisper-large-v3 (36.86), Qwen3-ASR-1.7B (33.69), gemma-4-E4B (32.98); rank-1 is a 2.35B system (23.17). Per-set: MGB-2 (Egyptian broadcast) **18.15 WER / 8.01 CER**, MASC clean 13.04, CV18 20.69, SADA 41.95, Casablanca 58.86.
- Measurement hygiene is unusually strong: all 1.79M training clips audio-fingerprinted against the 46,846 test clips, 0.00% MGB-2 and CV18 overlap, re-scored delta -0.007 WER.
- Egyptian relevance: the MGB-2 row is genuine Egyptian-domain attestation, but the model is pan-Arabic; there is no Egyptian-only test number. Output is undiacritized Arabic without punctuation and with a known t-marbuta/ha inconsistency (about 0.7 WER on the 6-set average if folded), same output convention as our dialectal entries.
- Size/runtime: int8 encoder 59MB + decoder 8MB + joiner 1.5MB (~69MB total). Realtime 69x on 2 CPU threads, single pass at any length (no 30s window). BUT the published ONNX is shaped for onnxruntime-web with features computed OUTSIDE the graph (features [1,128,T] input, stateful LSTM decoder steps); it is NOT sherpa-shaped. A sherpa port would ride the NeMo-transducer/Parakeet export approach (sherpa master gained NeMo transducer support work in v2.0.0: PRs #3952, #3895), which is plausible but unproven for this checkpoint.
- Score if the license existed: 7.6/10 (quality 4, size 5, on-device 3, breadth 3, importability 3, maintenance 4). Today: **not catalogable, license missing is a hard blocker for redistribution.**

Sources: https://huggingface.co/oddadmix/Nawah-ASR-60M-Max-Arabic , https://huggingface.co/oddadmix/Nawah-ASR-60M-Max-Arabic-ONNX , leaderboard referenced by the card: https://huggingface.co/spaces/elmresearchcenter/open_universal_arabic_asr_leaderboard

Also noted from the same leaderboard orbit: `audarai/Audar-ASR-V1-Flash` (0.78B, rank 10 at 32.04 avg, GGUF + transformers, custom "Audar Open License v1.0") is worse than Nawah at 12x the size; GGUF has no runtime in the app. Watch-list only. https://huggingface.co/audarai/Audar-ASR-V1-Flash
