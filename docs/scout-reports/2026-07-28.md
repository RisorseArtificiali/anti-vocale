# Model Scout Report - 2026-07-28

**Scope:** Full (ASR, LLM, Frameworks, Landscape)
**Baseline:** sherpa-onnx 1.13.4, LiteRT-LM 0.13.1, Parakeet TDT v3 int8 (default), Whisper Distil-IT/Turbo/Small, Qwen3-ASR 0.6B, Nemotron streaming, Gemma 4 E2B/E4B via LiteRT-LM
**Last report:** 2026-07-20

## Executive Summary

No new sherpa-onnx release since v1.13.4 (still current). The ASR landscape continues to consolidate around speech-LLM hybrid architectures. Two findings warrant attention: **FunASR Nano MLT** (multilingual variant with Italian, ONNX-ready for sherpa-onnx) and **CrispASR** (a new C++/ggml runtime that unifies 16+ ASR families, though not Android-ready). The **GLM-ASR-2512** from Z.AI is a new speech-LLM model worth watching. Gemma 4 12B released but is too large for on-device mobile use.

## Findings

### 1. FunASR Nano MLT - Multilingual Variant with Italian (SCORE: 3.6/5)

**What:** `FunAudioLLM/Fun-ASR-MLT-Nano-2512` is the multilingual variant of FunASR Nano. It uses a SenseVoice encoder + Qwen3-0.6B LLM decoder architecture (~0.8B params). An int8 ONNX export exists (`luigi000/fun-asr-mlt-nano-onnx-int8`) packaged for sherpa-onnx's `OfflineRecognizer.from_funasr_nano`.

**Language coverage:** Multilingual (MLT = Multi-Language Transcription). The original SenseVoice covers 50+ languages including Italian. The MLT Nano variant inherits this coverage.

**Size:** ~0.8B params, int8. Exact ONNX file size unverified but likely 400-600MB range (comparable to Parakeet TDT 0.6B int8 at 464MB).

**sherpa-onnx integration:** Already supported via `OfflineRecognizer.from_funasr_nano()`. The sherpa-onnx docs list `sherpa-onnx-funasr-nano-int8-2025-12-30` as a pre-trained model (though that specific one is zh/en/ja only). The MLT variant from `luigi000` is a community export.

**Italian quality:** SenseVoice (the encoder) has demonstrated Italian support. The MLT variant adds Qwen3 LLM decoder which may improve contextual accuracy. No Italian WER benchmark found. Quality is likely below Parakeet TDT v3 (our current best) but the architecture is interesting.

| Criterion | Score | Notes |
|-----------|-------|-------|
| Italian quality | 3 | SenseVoice covers Italian, Qwen3 LLM helps; no WER data |
| Size efficiency | 4 | ~0.8B int8, likely 400-600MB, comparable to Parakeet |
| On-device feasibility | 4 | sherpa-onnx from_funasr_nano supported, CPU-only |
| Multilingual breadth | 4 | 50+ languages via MLT variant |
| Maintenance health | 3 | Community export (luigi000), not official csukuangfj |

**Recommendation:** Watch. The MLT multilingual variant with the speech-LLM architecture is promising for Italian quality, but needs Italian WER evaluation before integration. The community export (not csukuangfj official) is a risk. Check if csukuangfj publishes an official MLT variant.

### 2. CrispASR - C++/ggml Unified ASR Runtime (SCORE: 2.4/5)

**What:** `CrispStrobe/CrispASR` is a new C++ runtime that unifies 16+ ASR model families under one ggml-based engine: Whisper, Parakeet, Canary, Canary-Qwen, Cohere Transcribe, Granite-Speech, Voxtral-Mini, Qwen3-ASR, GLM-ASR, Kyutai-STT, FireRedASR, Moonshine, omniASR, and more.

**Architecture:** Uses ggml for inference (not ONNX Runtime). Speech-LLM backends (qwen3, voxtral, glm-asr, kyutai-stt) inject audio encoder frames directly into an LLM's input embeddings.

**Android feasibility:** Not yet. CrispASR targets desktop/server (x86_64, ARM64 Linux). No Android build or JNI wrapper found. Would require significant porting effort to replace sherpa-onnx.

**Relevance:** Not directly actionable for Anti-Vocale, but signals a trend: the ggml ecosystem is absorbing speech models, which could eventually provide an alternative to ONNX Runtime on mobile (ggml is lighter and already powers llama.cpp on Android via llama-bro).

| Criterion | Score | Notes |
|-----------|-------|-------|
| Italian quality | 3 | Supports Qwen3-ASR, Voxtral (both Italian-capable) |
| Size efficiency | 3 | ggml models are typically compact (Q4/Q8) |
| On-device feasibility | 1 | No Android build; desktop only |
| Multilingual breadth | 4 | 16+ model families, many multilingual |
| Maintenance health | 3 | Active GitHub repo, recent commits |

**Recommendation:** Watch only. If CrispASR adds Android ARM64 support, it could become a lighter alternative to sherpa-onnx for speech-LLM models. Not actionable now.

**Source:** https://github.com/CrispStrobe/CrispASR

### 3. GLM-ASR-2512 - Z.AI Speech Recognition Model (SCORE: 2.8/5)

**What:** `GLM-ASR-2512` is Z.AI's next-generation speech recognition model, described as enabling real-time speech-to-text. It's a speech-LLM architecture (audio encoder + LLM decoder).

**Language coverage:** Likely multilingual (GLM family has strong multilingual support), but specific language list not confirmed. Z.AI is a Chinese company with strong Chinese/English focus.

**Availability:** API-only (via Z.AI cloud). No open-weight download, no ONNX export, no sherpa-onnx integration.

**Relevance:** Currently not actionable for on-device use. But if open-weighted and ONNX-exported, it would be a strong candidate given GLM's multilingual quality.

| Criterion | Score | Notes |

| Italian quality | 2 | Unknown; GLM family has multilingual capability |
| Size efficiency | 2 | Unknown; API-only, no model size data |
| On-device feasibility | 1 | API-only, no open weights, no ONNX |
| Multilingual breadth | 3 | Likely multilingual, unconfirmed |
| Maintenance health | 3 | Active development by Z.AI |

**Recommendation:** Watch for open-weight release. Not actionable now.

**Source:** https://docs.z.ai/guides/audio/glm-asr-2512

### 4. sherpa-onnx QNN Model Releases (SCORE: 3.0/5)

**What:** sherpa-onnx released `asr-models-qnn-binary-3` (July 9, 2026), the third batch of Qualcomm NPU-compiled ASR models. Assets include Moonshine variants for QCS9100 (Qualcomm Snapdragon). 430 assets total.

**Relevance to Anti-Vocale:** Currently targets Qualcomm NPU hardware (QCS9100 specifically). Our app targets general ARM64 CPU inference. QNN models would only benefit Qualcomm Snapdragon devices, and would require runtime QNN detection and fallback logic. Not actionable for a general-purpose app, but worth watching if QNN support becomes broader (more Snapdragon SoCs).

**Source:** https://github.com/k2-fsa/sherpa-onnx/releases/tag/asr-models-qnn-binary-3

### 5. Gemma 4 12B - Too Large for Mobile (SCORE: 1.8/5)

**What:** Google DeepMind released Gemma 4 12B, a dense multimodal model with native audio support. Strips out traditional encoders entirely; vision and audio flow into the LLM backbone. Runs on 16GB laptops.

**On-device feasibility:** 12B dense model is too large for mobile (our current LLM ceiling is ~7.4GB GGUF for Gemma 4 E4B). Even heavily quantized (Q3), 12B would be ~5-6GB, pushing mobile RAM limits.

**Recommendation:** Not actionable. The E2B/E4B variants remain the right choice for mobile.

**Source:** https://www.marktechpost.com/2026/06/03/google-deepmind-releases-gemma-4-12b/

### 6. LiteRT-LM Updates (SCORE: 3.5/5)

**What:** LiteRT-LM continues active development:
- Swift package for macOS/iOS now available
- OpenAI API-compatible server mode added to CLI
- Agent skill support for creating standalone Android demo apps
- Gemma 4 Single Position MTP (2x faster decode on mobile GPUs)
- Still at v0.13.x (our version); no v0.14+ release found

**Relevance:** Our LiteRT-LM 0.13.1 is still current. The MTP speed improvements (2x decode on GPU) would benefit Gemma inference if we can bump to a version that includes it. Worth checking if v0.13.1 already has the Single Position MTP or if it requires a bump.

**Source:** https://github.com/google-ai-edge/LiteRT-LM

## Prioritized Recommendations

1. **Watch FunASR Nano MLT** for Italian quality evaluation. If csukuangfj publishes an official MLT variant with Italian coverage confirmed, it could be a strong alternative to Qwen3-ASR (similar speech-LLM architecture, potentially better multilingual coverage). Needs WER eval on Italian voice messages.

2. **Consider LiteRT-LM bump** to check if Single Position MTP is available (2x Gemma decode speedup on GPU). Low-risk version bump with potential inference speed benefit.

3. **No new sherpa-onnx release** to upgrade to. v1.13.4 remains current.

4. **CrispASR is the most interesting landscape development** (ggml-based unified ASR runtime), but not actionable for Android yet.
