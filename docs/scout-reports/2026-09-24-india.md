# Model Scout Report: Indian Languages (hi, ta, te, bn, mr, gu + the full 22)

**Date**: 2026-09-24
**Scope**: `languages:hi,ta,te,bn,mr,gu` (triggered by the maintainer's India-adoption question)
**Baseline**: sherpa-onnx v1.13.8; catalog = 15 entries, ZERO with an Indian-language code

## Executive summary

The India gap is real and structural: no built-in model, no community-catalog entry covers ANY of the 22 scheduled languages. The good news: the landscape has a clear winner, a sherpa-onnx-ready export already exists, and it is Apache-2.0. **ai4bharat/IndicConformer (600M, MIT)** covers all 22 languages with community-measured WER of 7.65% (Hindi) to 31.5% (Malayalam); the per-language CTC exports by parismitaglobalsolutions ship int8 ONNX (~190MB per language + shared tokens) loadable by sherpa's `from_nemo_ctc`, exactly our existing CTC family. Catalog entries for hi/ta/te/bn/mr/gu would reach users TODAY without an app release.

## Findings

### 1. AI4Bharat IndicConformer 600M (per-language int8 CTC export), 8.4/10

- **Source**: upstream [ai4bharat/indic-conformer-600m-multilingual](https://huggingface.co/ai4bharat/indic-conformer-600m-multilingual) (522K downloads, MIT, ONNX in repo); sherpa export [parismitaglobalsolutions/indicconformer-sherpa-onnx](https://huggingface.co/parismitaglobalsolutions/indicconformer-sherpa-onnx) (Apache-2.0 packaging, updated 2026-09-22; per-language folders `hi/model.int8.onnx` 197.6MB verified via the HF tree API, plus shared `tokens.txt`).
- **Quality** (community benchmark, [Mohanaspiringcoder/indicconformer-asr-benchmark](https://github.com/Mohanaspiringcoder/indicconformer-asr-benchmark), RNNT decoding, 100 samples/language): hi **7.65%**, bn **9.68%**, mr **9.58%**, gu **9.88%**, pa 9.36%, kn 13.12%, ta **19.24%**, te **22.09%**, ml 31.5%. Not our harness, not voice-message-domain: confidence MEDIUM for hi/bn/mr/gu, LOW for ta/te (agglutinative scripts score worse everywhere).
- **Cross-check**: on the Vaani Hindi benchmark (multi-reference, hard) the conformer does not appear; Qwen3-ASR-0.6B (a model we SHIP) scores **20.6** there vs whisper-large-v3 26.8, so our existing Qwen3 entry already carries nontrivial Hindi capability nobody has advertised.
- **On-device**: 190MB int8 per language, CTC (no decoder/joiner), 16kHz mono, `from_nemo_ctc` = our `nemo_ctc` family (the exact config the omnilingual entry rides). Budget-Android-proven: the exporter's own Android app ships these files.
- **Scores**: quality 4 (hi-class) / size 5 / feasibility 5 / coverage-gap 5 (fills 22 languages we serve zero of) / importability 5 (stock CTC family) / maintenance 4.
- **Import path**: community-model-conversion skill, validation-first; entry JSONs pin `model.int8.onnx` + the SHARED tokens.txt (import-order constraint: tokens must be fetchable per-entry; if the shared file breaks per-entry pinning, mirror per-language copies under our org).

### 2. Qwen3-ASR 0.6B (already shipped), the unadvertised India option, 6.5/10

- Vaani Hindi 20.6 (beats whisper-large-v3's 26.8 on the same benchmark). Our catalog declares its 59 languages without calling out hi. **Zero-work action**: the Models-tab filter and store listing can surface "Hindi" on the existing entry today.
- No per-language advantage over IndicConformer on hi (7.65% community vs 20.6 hard-benchmark are not directly comparable), but it is ALREADY INSTALLED for existing users.

### 3. Hinglish (hi-en code-switch), niche differentiator, watch

- The same export repo carries Oriserve Whisper fine-tunes (`hi-hinglish-apex` ~1GB, `hi-hinglish-swift` ~150MB, Apache-2.0) loaded via `from_whisper` = our WHISPER family. Code-switched Hinglish is the DOMINANT Indian voice-message register; nothing we ship handles it deliberately. The swift 150MB is a cheap catalog add if validation passes.

Validation-first on the Mac (eval harness + FLEURS/IndicSUPERB samples), then the standard conversion pipeline. This is the single highest-leverage India action available.
